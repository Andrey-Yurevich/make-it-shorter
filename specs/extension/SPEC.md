# Расширение Chrome

Manifest V3. Стек: React + TypeScript + Tailwind + shadcn/ui.

## Поверхности

| Поверхность | Что делает |
|---|---|
| **Side panel** | единственное место, где показывается результат: резюме, кнопки, две настройки над ним и кнопка обновления под ним |
| **Content script** | извлечение текста со страницы, плавающая иконка на выделении. Объявлен на `<all_urls>` |
| **Service worker** | открытие панели, контекстное меню, горячая клавиша, welcome/uninstall |

**Резюме не рисуется на странице.** Всё уходит в боковую панель. Одна поверхность вместо двух: не нужно бороться с чужим CSS на целой панели и дублировать рендер потока.

Единственное, что внедряется в страницу, — иконка на выделении. Она в Shadow DOM с обычным CSS: Tailwind в чужую страницу не попадает.

## Открытие панели

Все входы ведут в одну панель. **Каждый вход однозначно определяет, что будет сжато** — расширение не догадывается:

| Вход | Что сжимается |
|---|---|
| Иконка расширения в тулбаре | **вся страница** |
| Горячая клавиша | **вся страница** |
| Плавающая иконка на выделении | выделение |
| Контекстное меню на выделении | выделение |
| Кнопка обновления в панели | **вся активная вкладка** |

Иконка в тулбаре не просто открывает панель — она **запускает сжатие страницы**. Это единственный вход в этот режим, и он же самый заметный: пользователь, поставивший расширение, жмёт именно туда.

Из-за этого `openPanelOnActionClick` включать **нельзя**: с ним Chrome открывает панель сам, а `action.onClicked` не срабатывает, и запустить извлечение неоткуда. Вместо этого — `setPanelBehavior({openPanelOnActionClick: false})`, обработчик `action.onClicked` в service worker, оттуда `chrome.sidePanel.open({tabId})` и сообщение content script на извлечение. Клик по иконке — пользовательский жест, требование `open()` выполнено.

**Явное следствие, которое надо принять.** Есть выделение или нет, иконка в тулбаре сжимает страницу целиком. «Есть выделение — сожму его» выглядит умнее, но делает поведение самого заметного элемента непредсказуемым: результат зависит от невидимого состояния. Выделение имеет два собственных входа, и оба под рукой.

### Повторный клик по иконке

Панель уже открыта и в ней готовое резюме **той же страницы** (сравнение по URL вкладки) → клик просто фокусирует панель, запроса нет.

Без этого правила клик по иконке ради того, чтобы дочитать резюме, тратил бы запрос из дневной квоты и реальные деньги — при предгенерации уточнений цена одного запроса не символическая. Перечитать страницу намеренно — это кнопка обновления в панели, и она для того и одна: единственное место, где расширение тратит запрос по прямой команде пользователя.

URL сменился, вкладка другая, диалога нет → обычный запуск.

### Когда извлекать нечего

Content script на странице не работает (`chrome://`, магазин Chrome, просмотрщик PDF, `file://` без галочки), страница не похожа на статью по `isProbablyReaderable` или извлечение вернуло пустой текст — панель показывает, что на этой странице нет текста для сокращения, и подсказывает вставить текст в поле руками. Запрос не отправляется, квота не тратится, ошибкой это не считается.

**Пока сообщение на экране, кнопка «сжать страницу целиком» неактивна.** Активная кнопка под сообщением «прочитать не удалось» — это интерфейс, который спорит сам с собой: нажатие на той же вкладке может вернуть только то же сообщение.

Отсюда требование: **сообщение обязано истекать, иначе неактивная кнопка становится ловушкой.** Панель живёт на окно и переживает и переключение вкладок, и загрузку страниц, так что сообщение про вкладку, с которой пользователь уже ушёл, блокировало бы кнопку для той вкладки, на которую он пришёл. Поэтому сообщение привязано к вкладке — по `tabId`, не по URL: на служебных страницах, которые его и порождают, URL расширению не виден, `<all_urls>` схему `chrome://` не покрывает.

Снимается сообщение — и вместе с ним блокировка — в трёх случаях:

| Событие | Почему |
|---|---|
| активирована другая вкладка (`tabs.onActivated`) | перед пользователем другая страница, кнопка читает её |
| вкладка сообщения что-то загрузила (`tabs.onUpdated`) | содержимое могло появиться, пробовать или нет — решает пользователь |
| пользователь набрал или вставил текст в поле | он сделал ровно то, о чём просило сообщение |

Оба слушателя работают без разрешения `tabs`: нужен только `tabId`, URL здесь не смотрят. Заводить `tabs` ради этого нельзя — оно платится предупреждением при установке.

Остаётся один случай, когда кнопка неактивна, а могла бы сработать: страница отрисовала содержимое скриптом уже после извлечения, не сменив адрес и не выдав ни одного события. Выходов из него два — переключиться на другую вкладку и обратно или вставить текст в поле, — и оба у пользователя под рукой, поэтому четвёртого условия снятия нет.

**Проверить на раннем этапе:** `chrome.sidePanel.open()` требует пользовательского жеста и вызывается только из service worker — content script этот API не видит. Цепочка «клик в странице → сообщение → открытие» работает, но укладывается в окно жеста. Если сорвётся, запасной путь — открывать панель только по иконке в тулбаре, а плавающую иконку использовать для передачи текста в уже открытую панель.

Манифест: разрешение `sidePanel`, секция `side_panel` с `default_path`, секция `commands` для горячей клавиши, поле `key` с фиксированным ID (см. «Сборка»).

## Плавающая иконка на выделении

Появляется рядом с выделением по `mouseup`, если выделено больше минимума символов. Прячется при снятии выделения, прокрутке и Esc.

Размер 28×28, Shadow DOM, `z-index` у верхней границы, позиция считается от `getBoundingClientRect()` выделения с поправкой на края вьюпорта.

Не показывается в полях ввода и `contenteditable` — там выделение обычно означает правку, а не чтение.

## Бюджет content script

Скрипт исполняется на каждой открытой пользователем странице, включая тяжёлые. Расширение, заметно замедляющее чужие сайты, удаляют раньше, чем читают его описание.

Поэтому он делится надвое:

| Часть | Что внутри | Когда грузится |
|---|---|---|
| Резидентная | слушатель `mouseup`, отрисовка иконки, приём сообщений | всегда, объявлена в манифесте |
| Извлечение | Readability, нормализация текста | по требованию, динамическим `import()` |

Readability — сотни килобайт разбора DOM, и держать её на каждой вкладке ради функции, которую вызывают по контекстному меню, незачем.

Резидентная часть до первого `mouseup` не делает **ничего**: не трогает DOM, не ставит наблюдателей, не читает страницу. Верхняя граница — единицы килобайт.

**Проверить на раннем этапе:** прирост времени загрузки на тяжёлой странице. Заметен — сузить до `run_at: document_idle` с ленивой навеской слушателя после первого взаимодействия.

## Страницы, где content script не работает

Chrome не пускает расширения на служебные страницы (`chrome://`, `chrome-extension://`), в интернет-магазин Chrome, во встроенный просмотрщик PDF и на `file://` без отдельно включённой галочки.

Это не ошибка и не сообщается как ошибка. Иконки на выделении там просто нет, а панель говорит, что страницу прочитать не удалось, и держит кнопку чтения страницы неактивной, пока это сообщение на экране (см. «Когда извлекать нечего»). Автоматически расширение на такой странице сделать не может ничего, но тупика нет: поле ввода в панели работает всегда, и текст туда можно вставить руками.

Отдельный случай — вкладки, открытые до установки или обновления расширения. Там content script отсутствует, и его докладывают через `scripting.executeScript`; см. раздел о разрешениях.

## Извлечение текста

| Режим | Источник |
|---|---|
| Выделение | `window.getSelection()` |
| Вся страница | Readability.js (Mozilla), после проверки `isProbablyReaderable` |

### Есть ли на странице статья

Перед разбором страница проверяется `isProbablyReaderable()` из той же библиотеки. Это дешёвый вопрос по DOM: есть ли здесь тело текста, похожее на статью. Выдача поисковика, дашборд, лента карточек отвечают «нет» — и панель показывает то же сообщение, что для страниц, куда content script не пускают: текста для сокращения нет, вставьте его в поле руками.

Без этой проверки страница выдачи Google уезжала бы на сервер как сорок описаний чужих сайтов подряд. Сервер ответил бы `nothing_to_shorten`, но запрос и квота уже потрачены, а пользователь несколько секунд смотрел на пустой ответ. Хуже, если бы модель всё же «сократила» это — получилось бы более короткое перечисление сайтов, выданное за результат.

Проверка **не спорит с правилом «эвристик осмысленности нет»** из CLAUDE.md: она решает «есть ли здесь статья», а не «осмыслен ли текст», и делает это на DOM, где сигнал ещё есть, — ровно там, где по спеке ниже и должна решаться задача «содержание или обвязка». На плоском тексте такую проверку ставить нельзя.

Прошла проверка, а Readability всё равно ничего не вернула (форум, длинная ветка комментариев) — остаётся прежний запасной путь: видимый текст страницы как есть. Он хуже, но честнее, чем сказать пользователю, что страница нечитаема, когда она явно читаема.

### Нормализация

Три действия, и больше никаких:

1. обрезка пробелов по краям;
2. схлопывание подряд идущих пробелов и табуляций в один пробел, трёх и более переводов строки — в два (абзацы сохраняются);
3. обрезка до встроенного `maxInput` по code points.

**Грязный текст — допустимый результат.** Остатки навигации, «читать далее», подписи под картинками и прочий мусор, переживший Readability, оставляются как есть. Их читает модель, и стоят они несколько токенов.

Убирать мусор из плоского текста мы **не пытаемся**. Задача «что здесь содержание, а что обвязка» решается по DOM — по плотности ссылок, разметке, положению в дереве, — и решает её Readability, пока эти данные ещё есть. К моменту, когда на руках голый текст, сигнала уже нет, и любая чистка на этом слое сводится к угадыванию.

Прежняя формулировка «удаление повторяющихся блоков» убрана намеренно. Она не определена (что такое блок? что такое повторяющийся?), а любая её честная реализация ест содержание молча: припев в стихотворении, повторённую реплику в диалоге, одинаковые значения в колонке таблицы. Пользователь этого не увидит — он смотрит на резюме, а не на нормализованный текст, — и получит необъяснимый провал качества вместо понятной ошибки.

Мусор в резюме заметен и чинится настройками Readability. Съеденное содержание незаметно и не чинится ничем.

Библиотек ради этого не подключаем: три регулярки не стоят зависимости, веса в бандле и лишней строки в обосновании для ревью.

При обрезке — пометка в панели, что обработана часть текста.

## Проверка длины

Единственная проверка перед отправкой: длина после нормализации в пределах `[minInput, maxInput]`. Пороги встроены в сборку, на старте — 50 и 30 000.

**Считается в Unicode code points: `[...str].length`, не `str.length`.** Второе даёт UTF-16-юниты, и любая эмодзи весит два, а не один. На тексте из эмодзи и на некоторых письменностях расширение насчитало бы вдвое больше сервера и отклонило бы то, что сервер принимает, — прямое нарушение правила «клиент не строже сервера».

Обрезка делается по той же единице: `[...str].slice(0, maxInput).join("")`. Суррогатная пара при этом не рвётся сама собой, отдельной защиты не нужно. Графемные кластеры не учитываем — эмодзи, развалившаяся ровно на 30 000-м символе, продукту безразлична.

Проверок на «осмысленность текста» нет. Определять, есть ли смысл в тексте, — работа модели, а не регулярных выражений: она же решает, предлагать ли кнопки.

Клиентская проверка не должна быть строже серверной: иначе расширение отклонит текст, который сервер бы принял. Действующие пороги живут на сервере и расширению не сообщаются — встроенные значения существуют только чтобы не гонять заведомо мусорный запрос. Из этого следует, как их выбирать: **с запасом в сторону мягкости.** Серверное ужесточение доедет само (`too_short` / `too_long`), серверное ослабление упрётся во встроенный порог.

## Side panel

### Структура

```
┌─────────────────────────────┐
│ [RUS🇷🇺 ▾]   [📄 Original ▾] │  язык вывода + тон
├─────────────────────────────┤
│                             │
│   текст → резюме            │  прокручиваемая область
│   → кнопки → раскрытия      │
│                             │
│                     ★★★★★   │  оценка, справа внизу
├─────────────────────────────┤

└─────────────────────────────┘
```

Своего заголовка панель не рисует. «make it shorter» над ней показывает сам Chrome, из `<title>` документа, и убрать его нельзя — а надпись рядом с ним делала бы название дважды на одном экране.

### Две кнопки сверху

| Кнопка | Значения | По умолчанию |
|---|---|---|
| Язык вывода | из списка поддерживаемых | язык интерфейса браузера |
| Тон | `original` и четырнадцать тонов, см. ниже | `original` |

Экрана настроек нет: настроек ровно две, и отдельный экран под них был бы мебелью вокруг двух списков.

### Тон

Степени сжатия больше нет: форма резюме одна — один абзац, — а выбирает пользователь **голос**, которым оно написано.

| Значение | В списке |
|---|---|
| `original` | 📄 Original |
| `diplomatic` | 🤝 Diplomatic |
| `formal` | 🎩 Formal |
| `professional` | 💼 Professional |
| `confident` | 💪 Confident |
| `friendly` | 😊 Friendly |
| `academic` | 🎓 Academic |
| `casual` | 😎 Casual |
| `simplified` | 🔤 Simplified |
| `bold` | 🔥 Bold |
| `empathetic` | 💛 Empathetic |
| `direct` | 🎯 Direct |
| `luxury` | 💎 Luxury |
| `persuasive` | 🧲 Persuasive |
| `engaging` | ✨ Engaging |

`original` — тон исходника сохраняется: формальный текст остаётся формальным, разговорный — разговорным. Остальные значения задают голос независимо от того, как звучит исходник. Что каждый из них значит для модели — в спеке бэкенда; расширение знает только идентификаторы и подписи.

Каждому тону соответствует свой эмодзи, он стоит перед названием и в кнопке, и в списке. Порядок в списке фиксирован: дефолт первым, дальше как в таблице.

**Тон запоминается.** Выбор пишется в `chrome.storage.local` в момент выбора и читается при каждом открытии панели: переживает закрытие панели, перезапуск браузера и обновление расширения. Сбрасывается на `original` только значение, которого текущая сборка не знает.

По сети едет идентификатор, подписи и эмодзи живут только в расширении. Список значений на сервере тот же; значение вне списка — `invalid_request`.

На кнопке языка — короткий код и флаг (`RUS🇷🇺`), в списке — эндонимы из `Intl.DisplayNames`. Флаг для английского, испанского и арабского — соглашение, а не факт: языку страна не соответствует, и таблица кодов выписана руками. Chrome под Windows флаги не рисует и показывает вместо них две буквы; это некрасиво, но читаемо.

**Смена любой из двух настроек не перезапускает запрос.** Она действует на следующий, а перезапустить — это кнопка обновления внизу. Иначе выбор языка тратил бы запрос из квоты незаметно для того, кто просто листал список.

Остаток дневной квоты не показывается — на старте это лишний элемент. Про лимит пользователь узнаёт, только когда упрётся.

### Кнопка обновления

Единственный элемент внизу и единственное место, где панель тратит запрос по своей инициативе. Читает **активную вкладку заново**, целиком, независимо от того, что сейчас на экране и откуда оно взялось.

Читает панель сама — `tabs.query` и то же извлечение, что у service worker, — а не просит об этом worker: worker может спать, и сообщение в порт, который в этот момент переустанавливается, потерялось бы без единого следа на экране.

Автоматического перезапуска при изменении страницы нет и не будет: следить за DOM чужой страницы ради этого пришлось бы постоянно, а каждый перезапуск — деньги и запрос из полусотни суточных. Решает пользователь, нажатием.

## Ничего не хранится

Панель держит **один диалог — тот, что на экране**. Истории нет: ни списка прошлых резюме, ни исходных текстов в `chrome.storage.local`. Обновление заменяет диалог, закрытие панели его теряет.

Уточнения по-прежнему сохраняются **все**, включая нераскрытые, — но в памяти панели, пока она открыта: они получены и оплачены, и раскрывать их можно в любом порядке, не ходя в сеть.

Установки, где история успела появиться, чистятся на обновлении: `storage.local.remove("history")` в `onInstalled`. Функции больше нет, и данные уходят вместе с ней, а не лежат в хранилище с текстами пользователя, которые некому прочитать. Туда же уходит ключ `ratio` прежней степени сжатия, которую заменил тон.

**Формулировка в описании и в интерфейсе.** Обещание «ваш текст не сохраняется» относится и к серверу, и теперь к самому расширению: текст не уходит с устройства никуда, кроме нашего сервера, и не сохраняется ни там, ни здесь.

## Сетевой запрос

Делается **из side panel**, не из content script и не из service worker.

Панель — обычный документ, живущий, пока открыта, и стрим приходит туда же, где рисуется. Service worker для этого не годится: Chrome выгружает его при простое.

**Каждый POST несёт заголовок `x-amz-content-sha256`** — SHA-256 сериализованного тела в hex, через `crypto.subtle.digest("SHA-256", ...)`. Это требование OAC перед Lambda Function URL: CloudFront не хэширует тело сам, без заголовка origin ответит 403. Локальный мок этого не воспроизводит — ещё одна причина гонять контрактный тест против реального стенда.

Content script занимается только извлечением текста и передаёт его в панель сообщением.

### Чтение потока

`fetch` + `ReadableStream`, разбор SSE своими руками. `EventSource` не годится: он умеет только GET и не позволяет выставить заголовки, а нам нужны и тело запроса, и `X-Device-Id`, и `x-amz-content-sha256`.

Значит, парсер SSE наш, и в нём есть ровно два места, где такие парсеры ломаются:

1. **`TextDecoder` обязательно с `{stream: true}`.** Без этого многобайтовый символ, разрезанный границей чанка, превращается в мусор — и заметно это будет только на кириллице, CJK и эмодзи.
2. **Кадр может быть разорван между чанками.** Сеть не обязана присылать `\n\n` целиком. Накопительный буфер, из него выбираются только полные кадры, хвост остаётся до следующего чанка.

Обе ошибки не воспроизводятся на локальном моке и на быстром соединении: там чанки приходят целыми кадрами. Ловятся только контрактным тестом против реального стенда или искусственным дроблением потока.

Комментарии (строки, начинающиеся с `:`) и события с неизвестными именами отбрасываются молча.

## Обработка потока

| Событие | Действие |
|---|---|
| `delta` | дописать текст резюме |
| `actions` | отрисовать кнопки **неактивными**; пустой массив — не рисовать ничего и не считать ошибкой |
| `answer` | найти кнопку по `id`, положить в неё текст, сделать активной |
| `done` | убрать индикатор; кнопки, оставшиеся неактивными, удалить. Payload игнорируется |
| `error` | показать сообщение по коду |

Индикатор снимается только по `done` или `error`.

### Пока первого токена нет

С момента нажатия и до первой `delta` панель показывает **силуэт будущего текста**: несколько полос разной длины на месте резюме и три прямоугольника на месте кнопок, всё пульсирует. Не спиннер и не надпись: заполняющаяся страница читается как «уже идёт», а крутящийся кружок — как «неизвестно сколько».

Тот же силуэт закрывает и чтение вкладки после нажатия кнопки обновления. Для пользователя это одно ожидание, а не два: он нажал и ждёт ответа, а из чего оно складывается — извлечение текста, сеть, модель — его не касается.

Появился первый токен — силуэт исчезает целиком и больше не возвращается: дальше текст дописывается на месте, а под ним висит обычный индикатор.

`{tokensIn, tokensOut}` в `done` — серверная бухгалтерия для контрактного теста и разбора жалоб. **Показывать их пользователю запрещено**, и панель не должна ломаться, если полей нет.

Кнопки появляются раньше своих текстов и несколько секунд стоят неактивными — это нормальный ход, а не подвисание. Неактивная кнопка показывает, что уточнение готовится: подпись видна, нажатие не срабатывает.

**Удаление по `done` — обязательный шаг.** Сервер не сообщает об отказе отдельного уточнения никаким событием: ID приехал в `actions`, `answer` к нему не пришёл, и `done` — единственный момент, когда становится ясно, что и не придёт. Пропустив этот шаг, получаем кнопку, которая никогда не нажмётся.

Ответ с кодом не 200 — транспортная ошибка: часть запросов отклоняет WAF и отдаёт обычный 403 без нашего протокола.

### Таймаут

**Один абсолютный срок: 60 секунд от начала запроса до `done`.** Истёк — поток отменяется, показывается `upstream_error`, **полученный текст остаётся на экране**: половина резюме полезнее пустоты и сообщения об ошибке.

Отдельного таймера на паузу между событиями нет, и это осознанно. Такой таймер был бы нужен, если бы сервер мог висеть неограниченно, но он не может: у функции жёсткие 50 с. Значит абсолютный срок в 60 с покрывает и случай «замолчал после трёх `delta`» — ради которого второй таймер и заводили.

Хуже того, второй таймер здесь активно вреден. Пауза между `actions` и первым `answer` — это вся фаза 2, до 25 с по серверному сроку, и она совершенно штатная. Любой таймер тишины пришлось бы ставить выше 25 с, то есть он почти никогда не срабатывал бы раньше абсолютного, — второй путь отказа ради нескольких секунд выигрыша в редком случае.

60 против серверных 50 — запас на сеть и на CloudFront (60 с на чтение origin). Клиентский срок обязан быть не меньше серверного, иначе расширение сдаётся раньше, чем функция отвечает, и пользователь видит ошибку там, где ответ уже шёл.

## Кнопки

Подпись берётся из `_locales/<lang>/buttons.json` по ID. ID без подписи молча пропускается — логировать это не нужно, читать такие логи некому.

**Клик в сеть не ходит.** Текст уточнения приехал вместе с резюме и лежит в памяти панели; нажатие раскрывает его под резюме. Ни запроса, ни ожидания, ни индикатора загрузки, ни состояния ошибки у кнопки не существует.

Повторное нажатие сворачивает раскрытое. Раскрытых уточнений может быть несколько одновременно — прятать одно при раскрытии другого незачем, всё уже на устройстве.

## Виджет оценки

Пять звёзд в правом нижнем углу панели. При наведении подсвечиваются звёзды слева направо до текущей.

Клик → переход на `https://make-it-shorter.net/rate-us?stars=<1-5>`. Дальнейшая логика на стороне лендинга, расширение о ней не знает.

Скрывается навсегда после оценки или закрытия крестиком.

> **Решение принято: развилка остаётся.** Риск известен и принят осознанно, ниже он записан, чтобы к нему можно было вернуться.
>
> Развилка «низкая оценка → форма, высокая → магазин» называется review gating. Apple запрещает это прямо; у Chrome Web Store формулировка мягче, но практика попадает под манипуляцию рейтингом и служила основанием для снятия расширений.
>
> Если магазин когда-нибудь предъявит претензию, правка минимальна и целиком на стороне лендинга: `/rate-us` начинает вести всех в магазин, а форму показывать рядом. Расширение не трогается и переиздания не требует — оно передаёт только `?stars=`.

## Настройки и хранилище

`chrome.storage.local`:

| Ключ | Значение | По умолчанию |
|---|---|---|
| `deviceId` | UUIDv4 | генерируется при установке, лениво пересоздаётся |
| `lang` | код языка резюме | язык интерфейса, нормализованный |
| `tone` | идентификатор тона, см. «Тон» | `original` |
| `catalogVersion` | целое | из сборки |
| `rated` | оценка поставлена или скрыта | false |

Пользовательских текстов здесь нет ни в каком виде — см. «Ничего не хранится».

`chrome.storage.sync` не используется: квота привязана к устройству намеренно.

### `deviceId`

Генерируется через `crypto.randomUUID()` при установке. **Пропал из storage — создаётся заново при первом же обращении, молча.** Пользователю ничего не сообщается, ошибкой это не считается: он чистил данные браузера, а не ломал расширение.

Пропасть он может буднично — пользователь очистил данные сайтов, завёл новый профиль, переставил расширение.

**Прямое следствие: дневная квота обходится в один клик.** Записано здесь, чтобы никто не принял её за защиту. Квота — вежливая просьба не злоупотреблять, рассчитанная на обычного пользователя, который чистить storage ради лишних запросов не станет. От настоящего злоупотребления защищает rate limit на WAF по IP, и только он.

Сделать иначе можно только через учётные записи — а это регистрация, хранение персональных данных, политика приватности и декларация в магазине. В MVP их нет и не планируется, поэтому дыра принята сознательно, а не упущена.

## Конфиг

Расширение не запрашивает конфиг с сервера и не хранит его. Пороги длины и список языков встроены в сборку; действующие значения живут на сервере, применяются им же и приходят обратно кодом ошибки.

Аварийный выключатель приезжает тем же путём: код `service_disabled` в ответе на обычный запрос. Панель переходит в состояние «сервис выключен» и не отправляет новых запросов до перезагрузки панели или явного повтора пользователем. Состояние в `chrome.storage` не сохраняется — иначе выключатель пришлось бы уметь ещё и выключать.

Пришло поле `message` — показывается как есть (английский). Не пришло — своя локализованная строка.

## Локализация

**30 языков на старте:**

`en` `es` `zh-Hans` `zh-Hant` `hi` `ar` `pt-BR` `ru` `ja` `de` `fr` `ko` `it` `tr` `pl` `nl` `id` `vi` `th` `uk` `fa` `ms` `sv` `cs` `ro` `el` `hu` `da` `fi` `he`

Язык интерфейса браузера вне списка → английский.

Строки интерфейса — `chrome.i18n`, `_locales/<lang>/messages.json`.
Подписи кнопок — `_locales/<lang>/buttons.json`, ключи совпадают с ID каталога.

### Требования к качеству перевода

Подписи кнопок — самый заметный текст в продукте, и плохой перевод здесь виден сразу.

1. **Двойная проверка.** Перевод делается одним проходом, вычитывается вторым — независимым, без доступа к первому варианту. Расхождения разбираются вручную.
2. **Длина не больше 24 символов.** Длинный вариант переформулируется, а не обрезается.
3. **Никаких идиом.** «What's the catch» на английском хорошо, на 29 языках — плохо. Формулировки буквальные.
4. **Обратный перевод для проверки смысла**: перевод на язык → обратно на английский → сравнение с оригиналом. Расхождение смысла означает переделку.
5. Для `ar`, `fa`, `he` панель выставляет `dir="rtl"`.

Генерация подписей в рантайме запрещена — только заранее подготовленные файлы.

## UI-состояния панели

| Состояние | Вид |

| Пусто | приглашение выделить текст или вставить свой |
| Загрузка | скелет в поле вывода до первого `delta`: три пульсирующие полосы на месте первых строк. Чтение страницы и ожидание первого токена для пользователя одно ожидание, и выглядят одинаково |
| Стриминг | текст печатается, кнопок нет, Copy нет |
| Кнопки готовятся | текст дописан, кнопки видны и неактивны |

| Готово без кнопок | только текст |
| Готово, наведение | всё поле вывода накрывается полупрозрачным перекрытием с надписью Copy посередине; клик в любом месте копирует, надпись на полторы секунды становится Copied. Колесо прокрутки под перекрытием доходит до текста. Перекрытие есть только у законченного текста: копировать половину ответа никто не имеет в виду |
| Раскрытие | готовый текст разворачивается под резюме, мгновенно |
| Ошибка | сообщение + повтор, кроме `rate_limited` |
| Сокращать нечего | по коду `nothing_to_shorten`: «здесь нечего сокращать, это не похоже на текст»; ввод остаётся в поле, чтобы его поправить или заменить |

## Логотип

Три горизонтальные полосы убывающей длины — текст, ставший короче. Читается на 16 пикселях, не требует деталей, не привязан к языку.

Исходник — `assets/logo.svg`. Растровые размеры для магазина генерируются из него.

## Сборка

Артефакт — zip для Chrome Web Store.

**Инструмент — Vite.** Это требование. MV3 просит нестандартной сборки: манифест, отдельные точки входа для service worker, content script и панели, HMR при разработке.

**CRXJS — рекомендация, а не требование.** Плагин закрывает всё перечисленное из коробки, но у него бывали долгие периоды затишья, и его состояние надо проверить в момент реализации. Заброшен — берётся Vite с небольшим собственным плагином, который копирует манифест и раскладывает точки входа. Спека привязана к Vite, не к CRXJS.

`catalogVersion` подставляется из `catalog.json` автоматически, руками не проставляется.

### Фиксированный ID расширения

В манифесте заполняется поле `key` — публичный ключ расширения.

Без него ID распакованной сборки случаен и не совпадает с релизным. Тогда `Origin` не проходит правило WAF, и собственная отладка упирается в 403 — при том, что исключений по путям в этом правиле нет и заводить их ради разработки нельзя.

Порядок: завести элемент в Chrome Web Store, взять оттуда публичный ключ, положить в `key` и **закоммитить**. Ключ публичный, в репозитории ему ничего не грозит; приватный остаётся у магазина и к нам не попадает.

Типы SSE-событий пишутся здесь же, генерация из общей схемы не используется. Совместимость с сервером проверяется контрактным тестом на реальном ответе.

**Тест сборки:** у каждого ID из `catalog.json` есть подпись во всех 30 файлах `_locales/<lang>/buttons.json`. Не проходит — сборка падает.

Проверяются **все** ID, включая помеченные `deprecated`: такой ID больше не предлагается, но может приехать в ответе на запрос, отправленный старой сборкой, и подпись к нему обязана находиться.

Поля `description` и `instruction` расширению не нужны и в сборку не попадают — это машинный текст для модели. Из каталога расширение берёт только `version` и список `id`.

Разрешения в манифесте:

```
permissions:      storage, contextMenus, sidePanel, scripting
host_permissions: https://api.make-it-shorter.net/*, <all_urls>
content_scripts:  matches ["<all_urls>"], run_at document_idle, all_frames false
```

**Широкое разрешение запрашивается осознанно.** Плавающая иконка на выделении должна появляться на любом сайте — заранее знать, на каком именно, невозможно. Это и есть заявленная функция, и без `<all_urls>` она не реализуема ни в каком виде. Плата — более долгое ревью на первой подаче и предупреждение при установке; см. «Ревью и формулировки».

`activeTab` не нужен: объявленный content script уже даёт доступ к DOM, а `<all_urls>` перекрывает временное разрешение по жесту.

`scripting` нужен не для обычной работы, а для одного случая — вкладки, открытые **до** установки или обновления расширения, не содержат content script. Тогда `chrome.tabs.sendMessage` падает с «Receiving end does not exist», и обработчик докладывает скрипт через `chrome.scripting.executeScript`. Без этого пользователь после установки видит неработающее расширение, пока не перезагрузит вкладку, и списывает это на брак.

**Проверить на раннем этапе:** достаточно ли `matches` в `content_scripts` для `tabs.sendMessage` и `scripting.executeScript`, или host permission нужен отдельно. Если достаточно — убрать `<all_urls>` из `host_permissions`; предупреждение при установке от этого не изменится (его порождает уже сам content script), но ревьюеру останется обосновывать на одну строку меньше.

Не запрашиваются намеренно: `tabs` (заголовки и URL вкладок не нужны — с активной вкладкой работаем через `contextMenus` и сообщения), `unlimitedStorage`, `clipboardRead`, `downloads`.

Правило: **не запрашивать разрешений сверх необходимого для заявленных функций.** Оно не запрещает широкие разрешения — оно запрещает те, под которые нет функции в этой спеке.

## Ревью и формулировки

Широкий content script переводит расширение на длинный трек ревью и показывает при установке «Чтение и изменение ваших данных на всех сайтах». Это самый пугающий текст, который Chrome умеет показывать, и он появляется до того, как пользователь увидит хоть что-то из продукта.

Поэтому:

- **Обоснование для магазина пишется заранее**, а не в ответ на отказ: одна функция, ради которой нужен доступ (иконка на выделении), одно предложение о том, что расширение читает страницу только по действию пользователя и ничего не читает фоново.
- Заявление о единственном назначении (single purpose) формулируется как «сжатие текста», без перечисления смежных возможностей — перечисление ломает single purpose.
- **В описании магазина предупреждение объясняется прямо**, первым экраном, а не прячется: доступ нужен, чтобы показать иконку у выделенного текста; страница читается только когда пользователь сам это запросил; прочитанное уходит только на наш сервер и там не сохраняется.

Формулировка про сервер — та же, что в разделе «Ничего не хранится», и должна совпадать с ней дословно.
