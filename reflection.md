# Ревью спецификаций — рабочий список

Статусы: `[ ]` не обсуждено · `[x]` решено, внесено в спеки · `[-]` отклонено.

## А. Дыры, которые сломают продукт в рантайме

### A1. `[x]` OAC + POST требует `x-amz-content-sha256` от клиента

Когда Lambda Function URL закрыт через OAC, CloudFront подписывает запрос, но хэш тела
не вычисляет: для POST клиент обязан прислать SHA-256 тела в заголовке
`x-amz-content-sha256`, иначе Function URL отвечает 403. Документированное поведение AWS.
Сейчас заголовка нет ни в таблице заголовков CLAUDE.md, ни в спеке расширения.

**Предложение:** расширение считает SHA-256 сериализованного тела
(`crypto.subtle.digest`) и шлёт заголовок; добавить в таблицу заголовков CLAUDE.md
и в проброс заголовков CloudFront (infra).

### A2. `[x]` `Origin` может не отправляться на GET — мёртв аварийный выключатель

Запросы из страниц расширения к хосту из `host_permissions` идут в обход CORS.
На POST браузер ставит `Origin` всегда, на GET без CORS-режима — нет.
WAF-правило «только `chrome-extension://<ID>`, исключений нет» тогда режет
`GET /v1/config` → расширение молча живёт на встроенных значениях →
`enabled: false` до клиентов не доедет никогда.

**Решено:** эндпоинт `GET /v1/config` удалён целиком (см. A6). GET-путей в API
не осталось, правило по `Origin` действует на всё без исключений, поведение
Chrome на GET проверять не нужно — вопрос снят вместе с эндпоинтом.

### A3. `[x]` Заявленные разрешения не позволяют реализовать заявленный UX

Плавающая иконка требует content script на всех страницах — `matches: <all_urls>`,
что для ревью эквивалентно host permission, которую спека запрещает.
Извлечение страницы (Readability) требует доступа к DOM: через `activeTab` — только
после жеста на расширении и только с разрешением `scripting`, которого нет в списке.

**Решено: вариант А.** Иконка остаётся, content script объявляется на `<all_urls>`,
более долгое ревью принимается.

Внесено:

- манифест — `permissions: storage, contextMenus, sidePanel, scripting`,
  `host_permissions: api + <all_urls>`, `content_scripts` на `<all_urls>`;
- `activeTab` убран: объявленный content script уже даёт DOM, `<all_urls>`
  перекрывает временное разрешение по жесту;
- `scripting` оставлен ради одного случая — вкладок, открытых до установки или
  обновления, где content script отсутствует и его надо доложить;
- запрет переформулирован: «не запрашивать разрешений сверх необходимого для
  заявленных функций» — широкие разрешения не запрещены, запрещены те,
  под которые нет функции в спеке. Список намеренно не запрашиваемых приведён;
- новый раздел «Ревью и формулировки»: обоснование для магазина пишется заранее,
  single purpose — «сжатие текста», предупреждение при установке объясняется
  первым экраном описания; та же формулировка про сервер продублирована в CLAUDE.md;
- новый раздел «Бюджет content script»: резидентная часть — только слушатель
  `mouseup` и иконка, единицы килобайт, до первого `mouseup` не делает ничего;
  Readability и нормализация грузятся динамическим `import()` по требованию;
- новый раздел про страницы, где content script не работает (`chrome://`, магазин
  Chrome, просмотрщик PDF, `file://` без галочки): не ошибка, панель открывается
  в режиме ручного ввода.

Осталось проверить на раннем этапе: достаточно ли `matches` для `tabs.sendMessage`
и `scripting.executeScript` — если да, `<all_urls>` уходит из `host_permissions`
(предупреждение при установке не изменится); и прирост времени загрузки тяжёлой
страницы от резидентной части.

### A4. `[x]` `catalog.json` не специфицирован

Нет схемы, нет поля версии (откуда `catalogVersion` «из сборки»?), нет самих кнопок.
Модель выбирает ID из enum — но чтобы выбирать осмысленно, ей нужно знать, что каждый
ID означает. `/v1/expand` должен превратить `actionId` в инструкцию модели — текст
негде взять.

**Решено:** схема принята как предложена —
`{version: int, actions: [{id, since, description, instruction, deprecated?}]}`.

Внесено в CLAUDE.md: сама схема с таблицей «кто какое поле читает»; оговорка, что
`description` и `instruction` — английский машинный текст для модели, пользователю
не показывается и правило «подписи только в расширении» не нарушает; **`id` неизменен
навсегда** (сеть + ключ локалей + история у пользователя — переименование ломает три
места разом, ошиблись именем → новый ID, старый `deprecated`); инвариант
**`version` = максимальный `since`**; `deprecated` исключается из enum и промпта,
но остаётся в файле, и `/v1/expand` принимает такой ID наравне с остальными;
предупреждение, что правка `description` обнуляет prompt-кэш целиком, поэтому
косметика вносится пачкой.

Внесено в спеку бэкенда: раздел «Каталог в промпте» — таблица `id → description`
в статической части рядом с описанием инструмента; раздел «Промпт `/v1/expand`» —
`instruction` по `actionId`, неизвестный ID → `invalid_request`; тест сборки на
инварианты файла.

Внесено в спеку расширения: тест подписей охватывает и `deprecated`-ID;
`description` и `instruction` в сборку расширения не попадают.

**Наполнение каталога не сделано** — см. Q2, вопрос открыт.

### A5. `[x]` `/v1/expand` недоописан

Передаётся ли модели инструмент? Отправляется ли `actions`? Валидируется ли
`actionId` и длина `summary`?

**Решено сменой схемы: эндпоинта больше нет.** Уточнения ко всем предложенным
кнопкам генерируются в том же запросе, что и резюме, и уезжают вместе с ним.
Нажатие на кнопку в сеть не ходит.

Размен: платим за все уточнения всегда, хотя нажмут в лучшем случае на одно.
Взамен уточнение пишется, пока исходный текст в руках у сервера, — закрыт
конструкцией класс отказов «резюме есть, а ответить по нему не из чего».

Вопросы A5 при этом просто перестали существовать: `summary` от клиента больше
не приходит (не нужен ни лимит, ни валидация), `actionId` не приходит тоже,
правила «шли тот же текст» и «храни язык диалога» не нужны. Из исходного
предложения выжило одно — `actions` шлётся всегда.

Внесено в CLAUDE.md:

- протокол: новое событие `answer` `{id, text}`, жёсткий порядок
  `delta`* → `actions` → `answer`* → `done`; `answer` приходит целиком,
  без стриминга — пользователь в этот момент читает резюме;
- **`done` как точка сверки**: ID без своего `answer` клиент отбрасывает;
- раздел «Уточнения генерируются заранее, все сразу» с обоснованием размена;
- два потолка вместо одного (резюме 400, уточнение 250), худший случай
  1650 выходных токенов против прежних 400; порог алярма $20 → $40;
- максимум кнопок переквалифицирован из элемента интерфейса в множитель стоимости.

Внесено в спеку бэкенда:

- один эндпоинт вместо двух;
- конвейер: фаза 1 (`ConverseStream`, резюме + инструмент) → `actions` →
  фаза 2 (`Converse`, по вызову на ID, **параллельно**) → `done`;
- **вторая точка кэширования** после исходного текста: фаза 1 пишет, все вызовы
  фазы 2 читают. Без неё текст до 30 000 символов оплачивался бы шесть раз;
  отсюда требование держать блок инструмента в фазе 2 байт в байт, хоть он и не нужен;
- отказ отдельного уточнения не порождает ни события, ни кода ошибки, ни повтора;
- обрезка до `maxActions` — теперь самая дорогая из трёх проверок фильтрации,
  `maxItems` в схеме остаётся статичным;
- квота считает запрос клиента, а не вызовы модели;
- новые метрики: доля неудавшихся уточнений, доля входных токенов из кэша.
  Вторая ловит единственный отказ схемы, который виден только по счёту;
- таймаут функции 30 → 50 с.

Внесено в спеку расширения: обработка `answer`, кнопки появляются неактивными
и активируются по своему тексту, удаление неактивных по `done`, клик без сети,
история хранит все уточнения и открывается работающей без соединения,
клиентский таймаут 40 → 60 с.

Внесено в инфраструктуру: `max_actions`, `answer_timeout_seconds`, потолки по
тирам, цена чтения кэшированного входа в `model_prices`, таймаут функции 50 с,
таймаут чтения origin на CloudFront 60 с.

**Открытые следствия:** квота 50/сутки не менялась, хотя запрос подорожал примерно
вчетверо — смотрим на реальный расход и режем по факту (ручка серверная).
Троттлинг Bedrock из формальности стал первым, что сработает под нагрузкой:
до шести обращений на запрос, пять одновременных.

### A6. `[x]` `enabled: false` не обрабатывается на POST-эндпоинтах

Конфиг кэшируется сутки — выключив сервис, ещё сутки получаем запросы от клиентов
со свежим кэшем, и конвейер их честно обработает: шага «проверить флаг» нет,
кода ошибки нет.

**Решено, шире исходного предложения: `GET /v1/config` удалён.**

Разбор по полям показал, что эндпоинт не окупается ни одним из них. Пороги длины
и список языков на клиенте — не enforcement, а экономия round trip: сервер и так
проверяет их сам и отвечает `too_short` / `too_long` / `unsupported_language`,
а требование «клиент не строже сервера» и без того допускает неточную копию.
Аварийный выключатель через конфиг работал **хуже** прямого пути: кэш на сутки
плюс два независимых способа не сработать (A2 и отсутствие шага проверки здесь).

Взамен:

- шаг 0 конвейера — проверка флага доступности, до квоты и до Bedrock;
- код `service_disabled` в `ErrorCode`, необязательное поле `message`
  в payload события `error` (английский, показывается как есть);
- расширение держит пороги и список языков встроенными, выбранными
  **с запасом в сторону мягкости**: серверное ужесточение доезжает само,
  ослабление упирается во встроенный порог до следующего релиза;
- ключ `config` из `chrome.storage` убран.

Обещание «меняется без релиза расширения» сохранено целиком: значения по-прежнему
переменные окружения Lambda и правятся через `terraform apply`. Изменилось только
то, что клиент их не видит, а узнаёт результат кодом ошибки — мгновенно,
на первом же запросе.

**Цена решения, принята осознанно:** панель не может показать «сервис выключен»
до первого запроса; выключенный клиент всё равно тратит один вызов Lambda
(на масштабе MVP — шум, при необходимости трафик режется блокирующим правилом WAF
до функции).

## Б. Недосказанности — LLM придётся гадать

### B1. `[x]` Единицы счёта длины

JS `.length` — UTF-16-юниты, Go — руны. На эмодзи/CJK клиент насчитает больше
сервера и отклонит то, что сервер бы принял — нарушение «клиент не строже».

**Принято.** Обе стороны считают Unicode code points: `[...str].length` в JS,
`utf8.RuneCountInString` в Go. Внесено в CLAUDE.md (строка в таблице лимитов плюс
абзац с обоснованием рядом с правилом «клиент не строже»), в конвейер бэкенда
и в проверку длины расширения. Отдельно оговорено, что обрезка до `maxInput`
идёт по той же единице и не рвёт суррогатную пару.

### B2. `[x]` Таймаут покрывает только тишину до первого события

Поток, замолчавший после трёх `delta`, висит вечно.

**Предложение:** 40 с до первого события, 25 с тишины между событиями; обе отмены →
`upstream_error`, полученный текст остаётся на экране.

**Принято по сути, но реализовано иначе — предложение устарело вместе с A5.**

Второй таймер после перехода на предгенерацию не просто не нужен, а вреден: пауза
между `actions` и первым `answer` — это вся фаза 2, до 25 с, и она штатная. Любой
таймер тишины пришлось бы ставить выше 25 с, то есть он почти никогда не срабатывал
бы раньше абсолютного срока — второй путь отказа ради нескольких секунд выигрыша
в редком случае.

Вместо двух таймеров **один абсолютный срок: 60 с от начала запроса до `done`.**
Он покрывает и исходную дыру («замолчал после трёх `delta`»), потому что сервер
физически не может висеть дольше своих 50 с. Полученный текст при отмене остаётся
на экране — эта часть предложения принята как есть.

### B3. `[x]` Не определён вход в режим «вся страница»

Перечислены три входа в панель, ни один не запускает Readability.

**Решено иначе, чем предлагалось: вход — иконка расширения в тулбаре.** Клик по ней
не просто открывает панель, а запускает сжатие всей страницы. Горячая клавиша делает
то же самое. Выделение сохраняет свои два входа — плавающую иконку и контекстное меню.

Следствия, внесённые в спеку расширения:

- `openPanelOnActionClick` включать **нельзя**: с ним Chrome открывает панель сам,
  а `action.onClicked` не срабатывает, и запустить извлечение неоткуда. Вместо этого
  обработчик `action.onClicked` в service worker → `sidePanel.open({tabId})` +
  сообщение content script;
- **иконка сжимает страницу независимо от того, есть выделение или нет.**
  «Есть выделение — сожму его» умнее, но делает поведение самого заметного элемента
  зависимым от невидимого состояния;
- **повторный клик не тратит запрос**: панель открыта и в ней готовое резюме той же
  страницы (сравнение по URL) → просто фокус. Без этого правила клик ради того,
  чтобы заглянуть в историю, стоил бы запроса из квоты и реальных денег;
- страница нечитаема или Readability вернула меньше `minInput` → панель в режиме
  ручного ввода, запрос не уходит, ошибкой не считается;
- в манифест добавлена секция `commands`.

### B4. `[x]` CloudFront origin read timeout по умолчанию 30 с — ровно таймаут Lambda

Гонка на длинных ответах.

**Закрыто в рамках A5, с уточнённой цифрой.** Предгенерация уточнений потребовала
поднять таймаут функции, и связка выбрана так, чтобы не упереться в квоту AWS:
у CloudFront потолок origin read timeout — 60 с, выше только через поддержку.
Поэтому **функция 50 с, CloudFront 60 с** — десять секунд запаса без обращений
в поддержку. Бюджет: фаза 1 до ~20 с, срок фазы 2 — 25 с, итого 45 с.

### B5. `[x]` Обработка OPTIONS на CloudFront — велосипед, нереализуемый заявленным способом

CloudFront сам не отвечает на OPTIONS — нужна CloudFront Function; но благодаря
`host_permissions` CORS для расширения вообще не включается, preflight не случится.

**Принято.** Пункт из модуля `cdn` убран и заменён явной строкой «обработки `OPTIONS`
нет» с обоснованием — иначе кто-нибудь добросовестно вернёт его обратно как забытое.

### B6. `[x]` Аларм «ноль успешных ответов при обычном трафике» не выражается одной метрикой

**Принято.** `aws_cloudwatch_metric_alarm` с `metric_query`, окно 3 часа, условие
`Invocations >= min_invocations_for_alarm AND Successes == 0`. Переменная заведена.

Попутно всплыло следствие, которого в предложении не было: **`Successes` функция
обязана публиковать сама.** Штатная метрика Lambda не годится — ошибка, отданная
как SSE-событие `error`, для Lambda является успешным вызовом. Успех считается
по факту доставки `done`.

### B7. `[x]` Квота: граница суток и судьба сгоревшего запроса

**Предложение:** сутки по UTC; инкремент до вызова Bedrock; при `upstream_error`
не возвращается (MVP, отметить осознанно).

**Решено: граница суток по центральноевропейскому времени, остальное как предложено.**

Зона задана **именем IANA `Europe/Berlin`, а не смещением `+01:00`**: летом Германия
живёт на UTC+2, и с фиксированным смещением квота обнулялась бы в час ночи вместо
полуночи. С именованной зоной граница всегда в местную полночь; сутки перехода длятся
23 или 25 часов, для суточного счётчика это безразлично.

**Ловушка, отмеченная в спеке:** Go в Lambda базу часовых поясов не содержит,
`time.LoadLocation` на голом `provided.al2023` вернёт ошибку, и проглоченная ошибка
даёт молчаливый откат на UTC — то есть тихо не ту границу суток. База вшивается
импортом `_ "time/tzdata"`, ошибка загрузки зоны фатальна при старте функции.

Зона вынесена в переменную `quota_timezone`: это вопрос удобства аудитории,
а не корректности, и меняется без релиза.

Инкремент до вызова Bedrock, при `upstream_error` квота не возвращается — принято
как есть, с записанным обоснованием: компенсирующая операция на пути отказа сама
может не пройти, и это порождает вопрос «а что если не прошла и она».

Единица счёта — запрос клиента, а не вызов модели (закрыто ещё в A5).

### B8. `[x]` `ratio` нигде не определён содержательно

Промпт писать не из чего; потолок 400 токенов конфликтует с «light» на 30 000 символов.

**Принято.** Новый раздел «Степень сжатия» в спеке бэкенда: таблица трёх значений
через форму результата, а не через долю от исходника — модель не считает символы,
а на входе от 50 до 30 000 символов одна доля означает несопоставимые вещи.

Записано и то, ради чего пункт заводился: **потолок токенов — предохранитель,
а не цель.** Резюме, упёршееся в `maxSummaryTokens`, обрывается на полуслове и
является браком, а не «резюме максимальной длины». Промпт требует укладываться
заведомо ниже, поэтому `light` — это «три-пять абзацев», а не «как можно подробнее»,
и сохраняет **структуру** длинного текста, а не его подробности.

### B9. `[x]` «Удаление повторяющихся блоков» — неопределяемая эвристика

**Предложение было:** схлопывание подряд идущих одинаковых строк, не более.

**Решено жёстче: дедупликации нет вообще.** Даже схлопывание одинаковых соседних
строк выброшено — это MVP, и грязный текст объявлен допустимым результатом.

Нормализация делает три вещи: обрезка по краям, схлопывание пробелов и лишних
переводов строки, обрезка до `maxInput`. Всё.

Обоснование, записанное в спеку: мусор в резюме заметен и чинится настройками
Readability; съеденное содержание незаметно (пользователь видит резюме, а не
нормализованный текст) и не чинится ничем. Чистка мусора — задача по DOM,
её решает Readability, пока сигнал ещё есть; на плоском тексте сигнала нет.

Библиотеки не подключаются: устоявшиеся решения этого класса (Boilerpipe,
trafilatura, jusText) работают по DOM и живут в Python/JVM, а из JS-класса у нас
уже стоит Readability — она и есть индустриальный стандарт для этой задачи.
SimHash/MinHash решают дедупликацию **между** документами в корпусе, внутри одного
документа это тот самый failure mode. Схлопывание пробелов зависимости не стоит.

### B10. `[x]` Мелкие пины (пакетом, без обсуждения по одному)

Все внесены. Три закрылись по ходу других пунктов: `scripting` — в A3,
`alarm_email` и `min_invocations_for_alarm` — в B6, язык поля `message` — в A6.

**Wire-формат SSE** → CLAUDE.md, раздел «Формат кадра». `event:` + однострочный
`data:` + пустая строка; `id:` и `retry:` не используются — переподключения нет
и быть не может, ответ невоспроизводим. Сверх пина добавлен **heartbeat `: ping`
раз в 10 с во время фазы 2**: это единственный участок, где соединение законно
молчит до 25 с, а прокси такие соединения рвут.

**Перечень `invalid_request`** → спека бэкенда, закрытый список из семи пунктов
плюс «всё прочее нераспознанное». Соседние случаи разведены явно: `lang` вне
списка → `unsupported_language`, длина → `too_short`/`too_long`, неизвестный путь
→ 404 без SSE. Записано, что это баг клиента или подделка, а не ошибка
пользователя, — отсюда общее сообщение в интерфейсе.

**Payload `done`** → клиент игнорирует, показывать токены запрещено, отсутствие
полей не должно ломать панель.

**`deviceId`** → `crypto.randomUUID()`, ленивое пересоздание молча. Записано прямо:
**квота обходится в один клик**, это вежливая просьба, а не защита; от настоящего
злоупотребления работает только rate limit на WAF по IP. Иначе — учётные записи,
которых в MVP нет.

**Поле `key`** → публичный ключ из Chrome Web Store коммитится в манифест, ID
распакованной сборки совпадает с релизным, отладка проходит правило `Origin`.
Оговорено, что ключ публичный и репозиторию не вредит.

**`fetch` + `ReadableStream`** → `EventSource` не умеет POST и заголовков. Плюс два
требования к рукописному парсеру: `TextDecoder` с `{stream: true}` и буфер,
переживающий кадр, разорванный между чанками. Обе ошибки не воспроизводятся
на локальном моке — только контрактным тестом или искусственным дроблением потока.

**Сборка** → Vite как требование, CRXJS как рекомендация с оговоркой проверить
её состояние в момент реализации; заброшена — свой небольшой плагин.

## В. Вопросы, где решение за автором

### Q1. `[x]` Плавающая иконка (связано с A3)

Оставлена. Вариант А, разбор и внесённые правки — в A3.

### Q2. `[x]` Стартовый каталог кнопок

Сгенерировать стартовый набор (~20 ID с описаниями и инструкциями, `since: 1`)
в `catalog.json` при правке спек — или оставить в спеке только схему,
а наполнение сделать отдельной задачей?

**Решено: отдельная задача во время разработки бэкенда.** Сейчас кнопки
не изобретаются. Схема зафиксирована, файл пуст.

Причина, записанная в спеку бэкенда: `description` — критерий выбора для модели,
и подбирается он по её реальному поведению на реальных текстах, а не умозрительно
до первого прогона.

Перечислено, что этот файл блокирует: enum схемы, таблица `id → description`
в промпте, промпты фазы 2, `_locales/<lang>/buttons.json` и тест подписей.
Каркас всех пятерых пишется на пустом каталоге, наполнение приезжает одним заходом.

### Q3. `[x]` Review gating в `/rate-us`

Спека сама называет риск снятия из магазина. Оставить развилку 1–3/4–5
или вести всех в магазин, а форму показывать рядом? Рекомендация была: второе.

**Решено: развилка остаётся.** Рекомендация не принята, риск принят осознанно.

Формулировка в спеке переписана с «решение за вами» на «решение принято»,
а сам риск оставлен — с добавлением того, чего в нём не хватало: **если магазин
предъявит претензию, правка целиком на стороне лендинга.** `/rate-us` начинает
вести всех в магазин, расширение не трогается и переиздания не требует — оно
передаёт только `?stars=`. Цена ошибки здесь порядка часа работы, а не релиза.

### Q4. `[x]` WAF rate limit 60/5 мин на IP

Офис за одним NAT упрётся. Поднять до ~300 или оставить 60?

**Решено: оставить 60.** Расширение читают дома и в дороге, а не в офисе
за общим NAT. Обоснование записано рядом с правилом, чтобы низкая цифра
не выглядела недосмотром. Упрутся — поднимем, ручка в переменной.

### Q5. `[x]` `reserved_concurrency`

В переменных «по нагрузке» — нужна цифра. Предложение было: 10 на старт.

**Решено: 5.** Меньше предложенного, и не случайно: после перехода
на предгенерацию считать надо не по Lambda, а по Bedrock. Один запрос клиента —
до шести обращений к модели, пять одновременных, то есть пять функций дают
до тридцати параллельных вызовов. Упрёмся в квоты модели заметно раньше,
чем в лимиты Lambda. Цифра — потолок расхода на старте, а не расчёт под нагрузку.

### Q6. `[x]` CI

«Код Lambda деплоится отдельным шагом CI», но CI не описан.

**Решено: `make-release.sh` + S3 + переменная Terraform.** Пайплайн-сервиса нет.

Граница проведена по «собрать» / «выкатить»: скрипт собирает и кладёт архив
в `s3://mis-artifacts/lambda/<short-sha>.zip`, функция ссылается на объект,
а какой именно — решает переменная `lambda_version`. Выкат — правка переменной
и `terraform apply`.

Отличие от исходного предложения существенное: **скрипт не вызывает
`lambda:UpdateFunctionCode` и таких прав не имеет.** Иначе появляются два способа
изменить прод — через Terraform и мимо него, — и состояние, которое видит
Terraform, перестаёт соответствовать действительности; следующий `apply` откатит
функцию в неожиданный момент.

Побочные выгоды: **откат — это правка переменной на прежнее значение**, без
сборки, без git, без доступа к машине разработчика. Ключ содержит git-хэш,
поэтому меняется при каждой сборке и Terraform видит изменение без
`source_code_hash`.

Заведён модуль `artifacts` (приватный бакет с версионированием). Туда же кладётся
zip расширения — Terraform он не нужен, но магазин не отдаёт загруженное обратно,
а знать, какая сборка у пользователей, необходимо при разборе жалоб.

Отмечена курица-и-яйцо: `api` требует существующего объекта в S3, поэтому порядок
первого применения — `artifacts` → `make-release.sh` → `api`.
