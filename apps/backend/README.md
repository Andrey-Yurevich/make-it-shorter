# Lambda-обработчик

Спека — [`specs/backend/SPEC.md`](../../specs/backend/SPEC.md). Здесь только то, что нужно, чтобы собрать, запустить и настроить.

## Файлы

| Файл | Что в нём |
|---|---|
| `main.go` | старт, глобальная статика, роутинг по пути |
| `shorten.go` | конвейер шагов 0–7, читается сверху вниз |
| `request.go` | шаги 1–2: разбор тела и заголовков, нормализация языка, длина в code points |
| `quota.go` | шаг 3: переопределения по устройству и суточный счётчик |
| `bedrock.go` | фазы 1 и 2, точки кэширования, схема инструмента |
| `prompt.go` | статический промпт, общий блок, задачи фаз |
| `catalog.go` | чтение и проверка `catalog.json`, фильтрация ID |
| `sse.go` | кадры протокола и коды ошибок |
| `config.go` | переменные окружения и цепочка разрешения параметров |
| `logging.go`, `metrics.go` | запись в CloudWatch |

`catalog.json` лежит в корне репозитория и **не встраивается в бинарник**: `go:embed` не умеет читать за пределы модуля, а копия внутри `apps/backend` превратила бы один источник правды в два. Файл кладётся в архив рядом с `bootstrap`, функция читает его из рабочего каталога при старте и без него не стартует.

## Сборка и запуск

```
go test ./...                    # включая проверку catalog.json
../../scripts/make-release.sh    # сборка под arm64, zip, выгрузка в S3, печать метки сборки
```

Локально — тот же обработчик обычным HTTP-сервером, против настоящих Bedrock и DynamoDB:

```
LOCAL_ADDR=:8080 CATALOG_PATH=../../catalog.json <остальные переменные> go run .
```

`LOCAL_ADDR` в Lambda не выставляется никогда.

## Переменные окружения

Задаются в Terraform. Отсутствие или мусор в любой обязательной — фатальная ошибка при старте функции, а не сюрприз на живом запросе.

| Переменная | Обяз. | Что |
|---|---|---|
| `SERVICE_ENABLED` | нет | `false` — аварийный выключатель. Любое другое значение и отсутствие оставляют сервис включённым: опечатка не должна класть прод |
| `DISABLED_MESSAGE` | нет | английский текст к `service_disabled`, показывается как есть |
| `MIN_INPUT` / `MAX_INPUT` | да | пороги длины, code points |
| `LANGUAGES` | да | коды через запятую, в нормализованном виде: `en,ru,pt-BR,zh-Hans,…` |
| `ANSWER_TIMEOUT_SECONDS` | да | срок одного вызова фазы 2 |
| `QUOTA_TIMEZONE` | да | имя зоны IANA для границы суток, `Europe/Berlin` |
| `TABLE_NAME` | да | таблица DynamoDB |
| `METRIC_NAMESPACE` | да | пространство собственных метрик |
| `MAX_ACTIONS` | да | глобальный потолок кнопок, он же число в промпте |
| `TIER1_COUNTRIES` | нет | коды стран через запятую |
| `TIER1_MODEL` / `REST_MODEL` | да | идентификатор модели |
| `TIER1_MAX_SUMMARY_TOKENS` / `REST_MAX_SUMMARY_TOKENS` | да | потолок резюме |
| `TIER1_MAX_ANSWER_TOKENS` / `REST_MAX_ANSWER_TOKENS` | да | потолок одного уточнения |
| `TIER1_MAX_ACTIONS` / `REST_MAX_ACTIONS` | да | сколько кнопок оставлять после фильтрации |
| `TIER1_DAILY_QUOTA` / `REST_DAILY_QUOTA` | да | квота на устройство |
| `MODEL_PRICES` | да | JSON: `{"<model-id>":{"input":0.8,"output":4,"cacheRead":0.08,"cacheWrite":1}}`, доллары за миллион токенов |
| `CATALOG_PATH` | нет | путь к каталогу; в Terraform задан явно как `catalog.json`, а дефолт в коде оставлен для тестов и локального запуска |

**Набор тира обязателен целиком, все пять полей.** Пустое значение не означает «падай на дефолт» — падать некуда, тир и есть дно цепочки, а над ним лежит только переопределение по устройству. Глобальная база `default_*` живёт в Terraform и в функцию не попадает: в окружении лежат уже разрешённые числа. Правило общее для всех переменных здесь — **дефолт выписан явно**, за действующим значением не надо идти в код.

`TIER1_MAX_ACTIONS` и `REST_MAX_ACTIONS` не могут превышать `MAX_ACTIONS`, проверяется при старте: именно глобальное значение уезжает в промпт («propose at most N ids»), и оно обязано быть статичным, иначе префикс стал бы разным для разных клиентов и раздробил prompt-кэш. Тир, просящий больше, всё равно ничего бы не получил — модель не предложит больше, чем сказано в промпте.

## Что проверяется тестами

- `catalog.json` в корне проходит все инварианты сборки;
- фильтрация ID: неизвестные, версия клиента, обрезка, дубликаты;
- нормализация языка и счёт длины в code points;
- закрытый список `invalid_request` против `unsupported_language`;
- кадры SSE однострочные, `actions` пустой сериализуется как `[]`, ошибка едет под HTTP 200;
- сентинель «сокращать нечего»: промпт его называет, удержание начала потока правильно решает «ждать / отдать / проглотить»;
- порядок вокруг второй точки кэширования — единственная поломка в сервисе, которая ничего не ломает, а только умножает счёт.

Вызовы Bedrock и DynamoDB тестами не покрыты: моки на них проверяли бы моки. Проверяются они на стенде, см. порядок первого применения в спеке инфраструктуры.

## Что показал первый прогон

Замеры на `us.anthropic.claude-haiku-4-5-20251001-v1:0`, 2026-08-17:

- **`strict: true` принимается, но не вместе с `maxItems`** — схема с обоими отвергается на каждом запросе. Потолок кнопок переехал в промпт, см. «Инструмент» в спеке.
- **Две точки кэширования работают.** Фаза 1 пишет префикс, все вызовы фазы 2 читают его: на тексте в 16 000 символов `cacheWrite=4411` один раз и `cacheRead=17644` на четыре уточнения.
- **Минимальная длина кэшируемого префикса — 4096 токенов.** Ниже кэш не включается вообще: префикс на ~3935 токенов дал `cacheRead=0, cacheWrite=0`, на ~4411 — нормальное кэширование. На коротком входе фаза 2 платит полную цену каждым вызовом, и текст на 13 139 символов выходит дороже ($0,0236), чем на 16 000 ($0,0119). Расчёт стоимости на выделениях надо пересобирать под это.
- **128 МБ хватает:** `Max Memory Used: 33 МБ`, первый токен 1,1–2,5 с.

Осталось открытым:

- дважды из дюжины прогонов первый токен пришёл через ~22 с вместо 1,8. Компиляция грамматики после простоя не подтвердилась (контрольные 4 минуты тишины дали 2,9 с), троттлинга Bedrock за период не было вовсе. Причина не установлена, решение про прогрев без неё принимать рано;
- резюме упирается в потолок ровно на 400 токенах на длинных текстах — спека называет такое браком.
