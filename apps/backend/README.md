# Lambda-обработчик

Замысел и решения — в корневом `CLAUDE.md`, раздел «Бэкенд». Здесь только то, что нужно, чтобы собрать, запустить и настроить.

## Файлы

| Файл | Что в нём |
|---|---|
| `main.go` | старт, глобальная статика, роутинг по пути |
| `shorten.go` | конвейер шагов 0–5, читается сверху вниз |
| `request.go` | шаги 1–2: разбор тела и заголовков, нормализация языка, длина в code points |
| `quota.go` | шаг 3: переопределения по устройству и суточный счётчик |
| `bedrock.go` | вызов модели, точка кэширования, удержание начала потока |
| `prompt.go` | системный промпт, блок пользователя, сентинель |
| `sse.go` | кадры протокола и коды ошибок |
| `config.go` | переменные окружения и цепочка разрешения параметров |
| `logging.go`, `metrics.go` | запись в CloudWatch |

## Сборка и запуск

```
go test ./...
../../scripts/make-release.sh    # сборка под arm64, zip, выгрузка в S3, печать метки сборки
```

Локально — тот же обработчик обычным HTTP-сервером, против настоящих Bedrock и DynamoDB:

```
LOCAL_ADDR=:8080 <остальные переменные> go run .
```

`LOCAL_ADDR` в Lambda не выставляется никогда. Полный список переменных окружения — в `CLAUDE.md`, «Параметры запроса».

## Что показал первый прогон

Замеры на `us.anthropic.claude-haiku-4-5-20251001-v1:0`, 2026-08-17:

- **Минимальная длина кэшируемого префикса — 4096 токенов.** Ниже кэш не включается вообще: префикс на ~3935 токенов дал `cacheRead=0, cacheWrite=0`, на ~4411 — нормальное кэширование. Текущий системный промпт короче, точка кэширования стоит бесплатно.
- **128 МБ хватает:** `Max Memory Used: 33 МБ`, первый токен 1,1–2,5 с.
- Дважды из дюжины прогонов первый токен пришёл через ~22 с вместо 1,8. Троттлинга Bedrock не было, причина не установлена.
