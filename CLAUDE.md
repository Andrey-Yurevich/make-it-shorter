# make it shorter

Расширение Chrome: сжимает выделенный текст или страницу целиком и предлагает уточняющие кнопки, подобранные под конкретный материал.

Этот файл — сквозные требования: решения, затрагивающие больше одного пакета. Всё, что локально для пакета, — в его спеке.

| Спека | Что описывает |
|---|---|
| `specs/extension/SPEC.md` | Расширение Chrome |
| `specs/backend/SPEC.md` | Lambda-обработчик |
| `specs/infra/SPEC.md` | Terraform |

При конфликте этого файла со спекой пакета прав этот файл.

## Состав системы

| Пакет | Что | Стек |
|---|---|---|
| `apps/extension` | Расширение Chrome MV3 | TypeScript |
| `apps/backend` | Lambda-обработчик | Go |
| `infra/terraform` | Инфраструктура | Terraform |
| `catalog.json` | Каталог кнопок — единственное, что нужно обеим сторонам | JSON |

Расширение на TypeScript, бэкенд на Go. Общего кода между ними нет и быть не может — только общие данные, и они сведены к одному файлу.

## Что меняется без релиза расширения

Расширение проходит ревью в Chrome Web Store, это дни. Поэтому всё, что может понадобиться срезать срочно, живёт на сервере, а не в сборке расширения:

- пороги длины входа;
- дневная квота на устройство;
- потолок ответа модели;
- список языков;
- аварийный выключатель сервиса.

Расширение получает действующие значения через `GET /v1/config` и кэширует их в `chrome.storage` на сутки. Не достучалось — работает на встроенных значениях по умолчанию.

**Клиентская проверка не должна быть строже серверной.** При расхождении худшее, что случится, — лишний запрос, который сервер отклонит. Ложного отказа на клиенте не будет никогда, и совпадение логики до буквы не требуется.

## Домены

| Домен | Назначение |
|---|---|
| `make-it-shorter.net` | Лендинг, S3 + CloudFront |
| `api.make-it-shorter.net` | API, CloudFront → Lambda Function URL |

Лендинг и API не связаны, общего кода нет.

## Транспорт

**Один регион: `us-east-1`.** Lambda Function URL с `InvokeMode: RESPONSE_STREAM`, перед ней CloudFront.

Регион выбран по доступности моделей Bedrock: там они появляются раньше и шире всего, а выбор модели ограничивает весь продукт — нужны и strict tool use, и дешёвый быстрый класс.

API Gateway не используется: CloudFront перед функцией нужен в любом случае, шлюз добавил бы звено и стоимость без выигрыша. Стриминг он поддерживает — отказ не по этой причине.

- Перед функцией обязателен CloudFront: Function URL не даёт кастомных доменов.
- Function URL закрыт через OAC — прямые обращения в обход CloudFront отклоняются.
- Function URL не поддерживает стриминг внутри VPC. Функция живёт вне VPC.

### Почему одного региона достаточно

Рукопожатие TLS происходит на ближайшем узле CloudFront, а не в регионе лямбды, и он держит прогретые соединения до origin. Вызов Bedrock идёт внутри региона и от местоположения пользователя не зависит.

Далёкий регион удорожает только **время до первого токена**: запрос и первый токен едут через полмира. Дальше труба уже открыта, и токены идут потоком — каждый следующий не платит round trip заново. Есть постоянное смещение, но частота, с какой текст появляется на экране, не меняется.

Мультирегион купил бы сотни миллисекунд до начала ответа ценой: региональных сертификатов, API Gateway вместо Function URL (иначе нет latency-роутинга), Global Table с неатомарной квотой через границу регионов и агрегации метрик. Для MVP размен не окупается.

## Протокол

SSE. Кодировка UTF-8, `Content-Type: text/event-stream`.

| Событие | Payload | Частота |
|---|---|---|
| `delta` | `{text: string}` | много раз |
| `actions` | `{ids: string[]}` | ровно один раз |
| `done` | `{tokensIn: number, tokensOut: number}` | один раз, штатное завершение |
| `error` | `{code: ErrorCode}` | вместо `done` |

**`actions` и `done` отправляются всегда**, включая случай пустого списка. Без них клиент не отличает «кнопок нет» и «завершено» от оборванного соединения.

`ids` может быть пустым — это валидный результат, а не ошибка. Означает «уточнять тут нечего»: мусорный ввод, слишком короткий текст, отсутствие предмета. Расширение в этом случае показывает резюме без кнопок, не считает это сбоем и ничего не подставляет вместо.

`docType` и `srcLang` модель возвращает вместе с кнопками, но клиенту они **не передаются** — расширение с ними ничего не делает. Остаются на сервере, в логах.

### Коды ошибок

`too_short` · `too_long` · `rate_limited` · `unsupported_language` · `upstream_error` · `invalid_request`

## Заголовки запросов

| Заголовок | Обязателен | Назначение |
|---|---|---|
| `X-Device-Id` | да | UUIDv4, генерируется при установке, квоты |
| `X-Catalog-Version` | да | целое, фильтрация ID кнопок под версию клиента |
| `Origin` | да | `chrome-extension://<ID>`, проверяется на WAF |

`Origin` фильтрует WAF на CloudFront, не Lambda: отклонённый запрос не порождает вызова функции. Ответ в этом случае — обычный 403, без SSE. Клиент трактует любой не-200 как транспортную ошибку.

## Кнопки

Три правила, нарушение любого ломает продукт.

1. **Модель никогда не генерирует подписи.** Только идентификаторы из каталога, через strict tool use с enum в схеме.
2. **Отсутствие вызова инструмента — валидный результат.** Означает «уточнять нечего»: мусорный ввод, слишком короткий текст, отсутствие предмета. Подстановка дежурного набора кнопок при пустом результате **запрещена**.
3. **Подписи живут только в расширении.** По сети едут ID. Сервер не знает и не должен знать, как кнопка называется.

### Где лежит каталог

`catalog.json` в корне репозитория — единственное место, где список ID определён. Бэкенд собирает из него enum для схемы инструмента. Расширение берёт номер версии для заголовка и на сборке проверяет, что у каждого ID есть подпись во всех локалях.

### Версионирование каталога

Каждая запись каталога имеет поле `since: number` — версия каталога, в которой ID появился.

Сервер отдаёт только ID с `since <= X-Catalog-Version`. Фильтрация **после** ответа модели, на сервере. Помещать версионный фильтр в JSON-схему инструмента запрещено — это порождает разные схемы и дробит prompt-кэш.

Версия каталога увеличивается при добавлении ID. Удаление ID из каталога запрещено — только пометка `deprecated`, иначе ломаются старые клиенты.

## Языки

Разделяются три независимые сущности:

| Что | Чем определяется | Где живёт |
|---|---|---|
| Язык интерфейса | `chrome.i18n` | расширение |
| Язык подписей кнопок | тот же, что интерфейса | расширение, `_locales` |
| Язык резюме | параметр `lang` в запросе | передаётся на сервер |

**Промпт всегда на английском.** Локализация промпта запрещена: дробит prompt-кэш по числу языков, ухудшает следование инструкциям, требует синхронной правки N версий.

**Исходный язык текста не определяется и не передаётся.** Модель читает его сама. Возвращает его в вызове инструмента как `srcLang` — только для логов, клиенту не уходит.

**Язык вывода не определяется по региону или IP.** Источник — `chrome.i18n.getUILanguage()`, перебивается явной настройкой пользователя.

### Нормализация

BCP-47 приводится к белому списку с откатом: `ru-RU` → `ru`, `zh-TW` → `zh-Hant`, неизвестное → `en`.

Разделяются: `pt-BR`/`pt-PT`, `zh-Hans`/`zh-Hant`. Не разделяются: варианты английского, испанского, французского.

Список поддерживаемых кодов приходит с сервера через `/v1/config`. Нормализация реализуется на обеих сторонах отдельно; расхождение некритично, пока список расширения не шире серверного.

## Приватность

Инвариант: **сервер не хранит пользовательский текст нигде и никогда.**

- `/v1/expand` stateless — клиент пересылает исходник заново. Серверный кэш текстов запрещён.
- В CloudWatch не пишутся ни исходник, ни резюме, ни их фрагменты.
- В DynamoDB хранятся счётчик запросов по `deviceId` и, если заведено вручную, переопределения лимитов для конкретного устройства.

**История диалогов хранится локально**, в `chrome.storage.local` на устройстве пользователя, и на сервер не уходит. Обещание «текст не сохраняется» относится к серверу — формулировка в описании и в интерфейсе должна говорить именно так: не уходит с вашего устройства и не хранится у нас.

**IP-адреса не собираются.** Для географических тиров нужна страна, и её определяет CloudFront, передавая функции двухбуквенный код в заголовке. Адрес до кода не доходит.

Поле `email` в переопределениях — персональные данные. Пока оно пустое, обязательств не возникает; как только начнёт заполняться, нужны политика приватности, декларация в Chrome Web Store и способ удалить запись по запросу.

Разрешено логировать: длину входа, `docType`, `srcLang`, выбранные ID, латентность, токены, код ошибки, флаг пустого результата.

## Три состояния ответа

| Состояние | Условие | Что видит пользователь |
|---|---|---|
| Отказ на входе | длина вне `[minInput, maxInput]` | сообщение, обращения к модели нет |
| Резюме без кнопок | модель не вызвала инструмент | только текст |
| Резюме с кнопками | инструмент вызван | текст + 3–5 кнопок |

Проверяется только длина — на клиенте и повторно на сервере. Эвристик «осмысленный ли текст» нет: решать это — работа модели, она же не вызывает инструмент, когда уточнять нечего.

## Лимиты

| Параметр | Значение |
|---|---|
| Минимум входа | 50 символов после нормализации |
| Максимум входа | 30 000 символов |
| Максимум кнопок | 5 |
| Квота | 50 запросов в сутки на устройство |
| Потолок ответа модели | 400 токенов |
| Порог алярма по расходу | $20 в сутки |

Модель, квота и потолок токенов разрешаются на каждый запрос по цепочке: **переопределение для устройства → набор для географического тира → глобальный дефолт.** Все три уровня меняются без релиза расширения.

Значения в таблице — стартовые. Действующие приходят с сервера, см. «Что меняется без релиза расширения».

Квота и потолок токенов расширению не сообщаются вовсе: остаток запросов пользователю не показывается — на старте это лишний элемент интерфейса. При исчерпании приходит `rate_limited`, расширение показывает сообщение.

## Приоритеты MVP

Скорость выката. При выборе между «правильно» и «быстро» побеждает быстро — **кроме** трёх пунктов, которые дорого чинить задним числом:

1. Версия каталога в протоколе.
2. Проверка ID на сервере.
3. Stateless-сервер.
