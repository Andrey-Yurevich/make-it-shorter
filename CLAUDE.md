# Make It Shorter

Расширение Chrome: сокращает выделенный текст или статью целиком — возвращает тот же текст короче, на выбранном языке и в выбранном тоне. Боковая панель, один запрос, один результат.

Этот файл — единственный документ проекта. Отдельных спек нет; всё, что нужно знать о замысле и решениях, лежит здесь. Локальные детали пакета — в его README.

## Состав системы

| Пакет | Что | Стек |
|---|---|---|
| `apps/extension` | Расширение Chrome MV3 | TypeScript, React, Tailwind v4, shadcn/ui, Vite |
| `apps/backend` | Lambda-обработчик `POST /v1/shorten` | Go, стандартная библиотека + AWS SDK |
| `apps/reporter` | Отчёт по CloudWatch: CLI и вебхук Telegram-бота | Go, отдельный модуль |
| `infra/terraform` | Вся инфраструктура, один корень | Terraform |
| `landing/` | Статические страницы `/welcome`, `/uninstall`, `/rate-us` | HTML без сборки |
| `scripts/` | `make-release.sh`, `frontend-build.sh`, `smoke-test.sh` | bash |
| `assets/` | `logo.svg`, скриншоты для магазина | |
| `short-description.txt`, `long-description*.txt`, `keywords.md` | Листинг Chrome Web Store | |

Общего кода между расширением и бэкендом нет и быть не может — только общие данные: коды языков, идентификаторы тонов, коды ошибок. Каждая сторона держит свою копию, совместимость проверяется контрактно.

`apps/reporter` связан с бэкендом только форматом лог-записи, односторонне. Общего `go.work` нет намеренно: воркспейс свёл бы оба модуля к одному списку сборки, а версии AWS SDK у них разные, и артефакт лямбды поехал бы молча.

## Язык

**Обсуждение и этот файл — на русском. Всё в репозитории как артефакт — на английском:** код, имена, комментарии, коммиты, PR, промпты, строки логов и ошибок. Строки, которые показывает Chrome (имя, описание, тайтл иконки), живут в `_locales` на 30 языках. Строки самой панели — английские литералы в коде, не локализуются.

## Стиль кода

**Код Lambda пишется наивным и читаемым.** Прямолинейный последовательный код без слоёв абстракции; интерфейс заводится при второй реализации; повтор лучше преждевременного обобщения; стандартная библиотека и AWS SDK, каждая следующая зависимость требует обоснования; явное лучше умного; никаких DI-фреймворков, кодогенерации и рефлексии. Конвейер запроса должен читаться сверху вниз за один проход в одной функции — его правит человек без контекста, раз в несколько месяцев, под давлением.

На расширение правило действует мягче: React и shadcn — норма, но состояние панели — один редьюсер, а не архитектура.

**Границы процессов.** Всё, что приходит из другого контекста (сообщения `onMessage`, ответы `sendMessage`, порт), типизируется `unknown` и сужается читателем в `shared/messaging.ts`. `scripts/check-boundaries.mjs` это проверяет на сборке. Правило родилось из бага: аннотация листенера типом сообщения выключила проверку, `undefined` дошёл до поля ввода, React размонтировал панель, и она стояла пустой.

## Расширение

### Поверхности и разрешения

| Поверхность | Что делает |
|---|---|
| Service worker | открывает панель по клику на иконку, внедряет content script, извлекает текст, пересылает панели |
| Content script | внедряется по требованию через `scripting.executeScript`; извлечение текста (Readability), отслеживание выделения |
| Side panel | весь интерфейс и сетевой запрос |
| Окно вывода | результат в отдельном окне: прочитать, скопировать, закрыть |

```
permissions:       storage, sidePanel, activeTab, scripting
host_permissions:  https://api.make-it-shorter.net/*
```

**`activeTab` вместо `<all_urls>` — осознанно.** Доступ к вкладке даётся по клику на иконку расширения. Нет резидентного скрипта на каждой странице, нет предупреждения «чтение данных на всех сайтах», короткий трек ревью. Цена: выделение отслеживается только на вкладках, где по иконке кликали. Плавающая иконка у выделения, контекстное меню и горячая клавиша удалены вместе с `<all_urls>`; возвращать любое из них — значит возвращать и разрешение.

`openPanelOnActionClick` выключен: с ним `action.onClicked` не срабатывает и запустить извлечение неоткуда. Не запрашиваются: `tabs`, `contextMenus`, `unlimitedStorage`, `clipboardRead`.

### Вход и чтение текста

**Единственный вход — иконка в тулбаре.** Клик: открыть панель → внедрить `content.js` → извлечь: выделение, если оно непустое, иначе страница целиком → текст в поле ввода. **Запрос не отправляется никогда автоматически** — единственный способ потратить запрос и квоту — кнопка Shorten. Повторный клик по иконке перечитывает вкладку и заменяет поле; это и есть обновление после навигации. Выделение ≥ 50 символов на вкладке с внедрённым скриптом само попадает в поле. Во время стриминга поле ввода извне не подменяется.

Страница целиком: `isProbablyReaderable(document)` → Readability → откат на `body.innerText`. Проверка на «есть ли здесь статья» делается по DOM, где ещё есть сигнал (плотность ссылок, разметка); на плоском тексте эвристик осмысленности нет — это работа модели. Выдача поисковика, дашборд, лента карточек → «на этой странице нет читаемого текста, вставьте руками». Служебные страницы (`chrome://`, магазин, просмотрщик PDF, `file://` без галочки) — то же сообщение, не ошибка.

**Нормализация — ровно три действия:** обрезка краёв, схлопывание пробелов (три и более переводов строки — в два), обрезка до 30 000 code points с пометкой «прочитана часть». Грязный текст — допустимый результат: остатки навигации читает модель за несколько токенов, а любая чистка плоского текста ест содержание молча.

### Панель

Одна колонка: поле ввода со счётчиком → язык вывода и тон → Shorten → результат со счётчиком → полоса оценки внизу. Результат — markdown, рендерится `react-markdown` в ограниченный набор элементов (абзацы, жирный, списки, таблицы); заголовки рендерятся жирной строкой, HTML не рендерится. Copy кладёт плейн-текст и HTML; счётчик вывода считает плейн-текст. Кнопка «Open in window» открывает результат в отдельном окне (`chrome.windows.create`, тип popup); текст передаётся через `chrome.storage.session` — память браузера, не диск.

До первого токена — скелет, не спиннер. Поле результата не прокручивается вслед за текстом. Таймаут — один абсолютный, 60 с от старта до `done`; по истечении полученный текст остаётся на экране. Смена языка или тона действует на следующий Shorten, а не перезапускает текущий.

Все надписи — английские литералы, Sentence case. Светлая и тёмная тема по `prefers-color-scheme`. RTL (`dir="rtl"`) в выводе для `ar`, `fa`, `he`, `ur`.

Полоса оценки: пять звёзд → `https://make-it-shorter.net/rate-us?stars=N`, скрывается навсегда после клика или крестика. Развилка по оценке живёт на лендинге (review gating — известный риск, принят осознанно; чинится на лендинге без переиздания расширения).

### Хранилище

`chrome.storage.local`: `deviceId` (UUIDv4), `lang`, `tone`, `rated`. Больше ничего: **пользовательских текстов в хранилище нет ни в каком виде.** Панель держит один результат в памяти и теряет его при закрытии. `onInstalled` удаляет ключи прежних функций: `history`, `catalogVersion`, `ratio`. `storage.sync` не используется — квота привязана к устройству.

**`deviceId` пропал — пересоздаётся молча.** Следствие: дневная квота обходится очисткой данных браузера. Это записано, чтобы никто не принял квоту за защиту: она — вежливая просьба к обычному пользователю; от злоупотребления защищает rate limit WAF по IP.

### Сборка

Vite; манифест пишет плагин из `manifest.ts`. **Версия — из git-тега на HEAD** (`v1.2.3` или `1.2.3`; несколько тегов — старший численно), без тега — `0.0.0` с sha в `version_name`. `EXTENSION_KEY` (публичный ключ элемента магазина) даёт распакованной сборке магазинный id; без него `Origin` не проходит WAF и API отвечает 403. `content.js` собирается отдельным IIFE-файлом без импортов.

`npm run build` = проверка локалей → проверка границ → `tsc` → юнит-тесты → сборки. `scripts/frontend-build.sh` оставляет zip и распакованную копию в `build/extension/`.

## Что меняется без релиза расширения

Ревью в Chrome Web Store — дни. Поэтому всё, что может понадобиться срезать срочно, — переменные окружения Lambda, меняются `terraform apply`: пороги длины, квота, потолок токенов, модель, список языков, аварийный выключатель. **Канала доставки конфига на клиент нет намеренно:** расширение узнаёт о значениях по коду ошибки в ответе на обычный запрос. Кэш конфига отложил бы выключатель на срок кэша и добавил второй путь отказа.

**Клиентская проверка не должна быть строже серверной.** Встроенные пороги расширения (50 / 30 000) существуют только чтобы не гонять заведомо мусорный запрос. Ужесточение на сервере доезжает сразу, ослабление — только до встроенного порога, поэтому встроенные значения выбираются с запасом в мягкую сторону.

**Единица длины — Unicode code point на обеих сторонах:** `[...str].length` в JS, `utf8.RuneCountInString` в Go. `String.length` считает UTF-16-юниты, `len()` — байты; оба ломают правило выше на эмодзи, кириллице и CJK.

## Домены и транспорт

| Домен | Назначение |
|---|---|
| `make-it-shorter.net` | лендинг и служебные страницы, S3 + CloudFront |
| `api.make-it-shorter.net` | API, CloudFront → Lambda Function URL |

**Один регион, `us-east-1`** — по доступности моделей Bedrock. Lambda Function URL, `InvokeMode: RESPONSE_STREAM`, перед ней CloudFront с OAC (прямой доступ к Function URL закрыт). API Gateway не используется: CloudFront нужен в любом случае ради домена, шлюз добавил бы звено и стоимость. Функция вне VPC: Function URL не стримит внутри VPC, а Bedrock и DynamoDB доступны публично.

Один регион достаточен: TLS завершается на ближайшем узле CloudFront, далёкий регион удорожает только время до первого токена, дальше поток идёт без повторных round trip. Мультирегион стоил бы API Gateway (latency-роутинг), региональных сертификатов и неатомарной квоты в Global Table.

### Заголовки запроса

| Заголовок | Назначение |
|---|---|
| `X-Device-Id` | UUIDv4, квоты |
| `Origin` | должен начинаться на `chrome-extension://`, проверяется на WAF |
| `x-amz-content-sha256` | SHA-256 тела в hex. Требование OAC: CloudFront вписывает это значение в подпись SigV4, без него Function URL отвечает 403 |
| `CloudFront-Viewer-Country` | ставит CloudFront; страна для тира, IP до функции не доходит |

**Все эндпоинты — POST.** На POST браузер ставит `Origin` всегда, на GET из расширения — не обязательно, поэтому правило WAF действует на весь API без исключений по путям. Правило отсекает веб-страницы (подменить `Origin` скриптом нельзя), а не чужие расширения: конкретный id не проверяется — распакованная сборка выводит id из пути папки, а скриптовый клиент шлёт любой `Origin`. `OPTIONS` не обрабатывается: расширение ходит на хост из `host_permissions`, preflight не случается.

## Протокол

SSE, UTF-8, `Content-Type: text/event-stream`, `Cache-Control: no-store`. Кадр: `event: <имя>\ndata: <JSON в одну строку>\n\n`. Многострочного `data` не бывает — `json.Marshal` экранирует переводы строк, парсер клиента на это опирается. `id:`/`retry:` не используются: ответ невоспроизводим, повтор — новый запрос и новый счёт. Комментарии и неизвестные события клиент игнорирует.

| Событие | Payload | |
|---|---|---|
| `delta` | `{text}` | много раз |
| `done` | `{tokensIn, tokensOut}` | один раз, штатное завершение; клиенту не показывается |
| `error` | `{code, message?}` | вместо `done` |

**`done` отправляется всегда** — без него клиент не отличает «завершено» от оборванного соединения. Любая ошибка конвейера — HTTP 200 и одно событие `error`; не-200 клиент трактует как транспортную ошибку (`upstream_error`).

Коды: `too_short` · `too_long` · `rate_limited` · `unsupported_language` · `upstream_error` · `invalid_request` · `service_disabled` · `nothing_to_shorten`.

`nothing_to_shorten` — единственный код, который выносит модель, а не сервер (раздел «Сентинель»). `service_disabled` — аварийный выключатель, проверяется первым шагом; `message` приходит только с ним: заданный вручную английский текст, показывается как есть. Все остальные коды текста не несут, формулировки живут в расширении.

## Бэкенд

### Конвейер `POST /v1/shorten`

```
text   string
lang   string   код языка вывода
tone   simplified | professional | casual | direct
source selection | page | manual
```

0. `SERVICE_ENABLED` → `service_disabled`. До всего: выключенный сервис не тратит ни `GetItem`, ни инкремент.
1. Разбор тела и заголовков → `invalid_request`; `lang` вне `LANGUAGES` → `unsupported_language`.
2. Длина в code points по `MIN_INPUT`/`MAX_INPUT` → `too_short`/`too_long`. Дублирует клиентскую проверку намеренно: сервер — единственная инстанция.
3. Переопределение устройства (`GetItem`), разрешение параметров по тиру, квота (`UpdateItem` с условием) → `rate_limited`.
4. Bedrock `ConverseStream`; текстовые чанки → `delta`; первые символы удерживаются до проверки сентинеля.
5. `done`.

`invalid_request` — закрытый список: тело не JSON или с лишними полями; нет `text`/`lang`/`tone`/`source`; `tone` или `source` вне списка; `X-Device-Id` не UUIDv4. Это баг клиента, пользователю показывается общее «что-то пошло не так». Неизвестный путь — обычный 404 без SSE. `Origin` функция не проверяет — это WAF.

Stateless: текст живёт в памяти функции, пока идёт ответ. Health-эндпоинта нет; живость видна по метрике успехов.

### Bedrock и промпт

`ConverseStream`, `us.anthropic.claude-haiku-4-5-20251001-v1:0` через cross-region inference profile, `temperature 0.3` (дефолт 1.0 давал отказы и потерю половины содержания на пограничных текстах; ниже 0.3 тона сливаются). Один системный блок и точка кэширования после него: статика байт-идентична для всех запросов. Bedrock кэширует префикс от 4096 токенов; текущий промпт короче, точка стоит бесплатно и размечает границу; `cacheReadShare` в логе покажет, когда кэш заработает.

**Промпт на английском, локализация запрещена** — дробит кэш, ухудшает следование инструкциям. Задание модели:

- **тот же текст короче, а не пересказ:** никакой речи со стороны («текст говорит», «автор призывает», жанр, форма), форма и лицо сохраняются (проза — проза, стих — стих, письмо от первого лица — письмо), выход всегда короче входа на любой длине. Числовой цели по объёму нет: модель не считает символы, а одна доля на 50 и на 30 000 символов означает несопоставимое;
- **роль — инструмент редактирования, как проверка орфографии:** текст не адресован модели, сокращение не есть одобрение, грубые тексты сокращаются как любые другие, отказ и объяснение запрещены. Отказ модели на сервере не детектируется — он многоязычен и без заданной формы;
- **тон меняет голос, не содержание и не объём;** применяется к сообщению, не судит его: на враждебном тексте решение, причина и требование остаются, накал уходит;
- **язык вывода задаётся по имени:** `Output language: Belarusian (be)`. Код сам по себе неоднозначен (`be` — глагол). Начинать писать на языке вывода с первого слова;
- **формат — минимальный markdown:** по умолчанию проза не длиннее абзаца; списки, таблицы (только если были в исходнике) и жирная строка-заголовок — только когда исходник структурирован или плохо читается; `#`-заголовки, ссылки, код, цитаты, HTML запрещены;
- **потолок токенов — предохранитель, не цель:** текст, упёршийся в `maxSummaryTokens`, — брак, промпт требует укладываться заведомо ниже. Постобработки длины на сервере нет.

Строки `Output language` и `Tone` лежат после точки кэширования — свои у каждого запроса.

### Сентинель «сокращать нечего»

Вход, не являющийся текстом (выдача поисковика, меню, лента заголовков, шум), — модель пишет ровно `[[NOTHING_TO_SHORTEN]]`. Сервер удерживает начало потока, пока накопленное — префикс сентинеля; сентинель целиком → `error: nothing_to_shorten` без `done`, ни одного `delta` клиент не получил; иначе удержанное уходит одним `delta`. Поток после сентинеля дочитывается ради учёта токенов. Ведущие пробелы не считаются. Квота не возвращается: модель отработала. Промпт оговаривает, что текст с остатками навигации — всё ещё текст. Сентинель в коде и в промпте — одна константа, проверяется тестом.

### Квота

DynamoDB, одна таблица, два вида записей по префиксу ключа `pk`:

| Ключ | Что | TTL |
|---|---|---|
| `quota#<deviceId>#<YYYY-MM-DD>` | счётчик за сутки | +48 ч |
| `device#<deviceId>` | переопределения: `model`, `maxSummaryTokens`, `dailyQuota`, `email`, `note` | нет, заводятся руками |

Инкремент — один `UpdateItem` с `ConditionExpression` на лимит; чтение с последующей записью запрещено — параллельные запросы обошли бы лимит. **Инкремент до вызова Bedrock**, поэтому запрос, упавший `upstream_error`, квоту не возвращает: компенсирующая запись на пути отказа сама может не пройти. Единица — запрос клиента.

Граница суток — местная полночь зоны `QUOTA_TIMEZONE` (`Europe/Berlin`), по имени IANA, не смещением. **Go в `provided.al2023` без базы зон:** `_ "time/tzdata"` в `main.go` обязателен, ошибка `LoadLocation` фатальна при старте — проглоченная означала бы UTC молча.

API самообслуживания для переопределений нет и не будет. `email` — персональные данные: пока пусто, обязательств нет; заполнение потребует политику приватности, декларацию в магазине и удаление по запросу. Чтение переопределения не удалось → запрос идёт на параметрах тира, с логом.

### Параметры запроса

Цепочка: **переопределение устройства → набор географического тира.** Тир — по `CloudFront-Viewer-Country` из `TIER1_COUNTRIES`, остальное `rest`; VPN даёт страну выхода, принимается как есть. **Набор тира задан в окружении целиком** — всякий дефолт выписан явно, за действующим числом не надо идти в код. База `default_*` живёт только в Terraform и накладывается на тиры в `locals`; функция её не видит.

Переменные окружения (задаёт Terraform; отсутствие или мусор — фатально при старте):

| Переменная | Что |
|---|---|
| `SERVICE_ENABLED` | `false` — выключатель; любое другое значение и отсутствие оставляют сервис включённым — опечатка не должна класть прод |
| `DISABLED_MESSAGE` | текст к `service_disabled`, необязательно |
| `MIN_INPUT`, `MAX_INPUT` | пороги длины, code points |
| `LANGUAGES` | коды через запятую; каждый обязан иметь имя в таблице имён функции |
| `QUOTA_TIMEZONE` | зона IANA |
| `TABLE_NAME`, `METRIC_NAMESPACE` | DynamoDB и пространство метрик |
| `TIER1_COUNTRIES` | коды стран через запятую, необязательно |
| `TIER1_MODEL`, `TIER1_MAX_SUMMARY_TOKENS`, `TIER1_DAILY_QUOTA` | набор тира 1, все обязательны |
| `REST_MODEL`, `REST_MAX_SUMMARY_TOKENS`, `REST_DAILY_QUOTA` | набор остальных, все обязательны |
| `MODEL_PRICES` | JSON `{"<model>":{"input","output","cacheRead","cacheWrite"}}`, $/млн токенов |
| `LOCAL_ADDR` | только локально: тот же обработчик обычным HTTP-сервером против настоящих Bedrock и DynamoDB |

### Логи, метрики, алармы

Одна JSON-запись на запрос, `event: "shorten"`: `inputLength`, `source`, `lang`, `tone`, `country`, `model`, `maxSummaryTokens`, `dailyQuota`, `firstTokenMs`, `totalMs`, `tokensIn/Out`, `cacheRead/WriteTokens`, `cacheReadShare`, `estimatedCostUsd`, `nothingToShorten`, `errorCode`. **Ничего из текста пользователя** — ни исходника, ни результата, ни фрагментов; ошибки Bedrock без эха запроса.

**Формат записи — контракт с `apps/reporter`:** он фильтрует `event = "shorten"`, суммирует `estimatedCostUsd` по `country`, читает `errorCode`. Переименование любого из них ломает отчёт и метрический фильтр аларма молча.

Функция публикует `EstimatedCostUsd` (расход считается по токенам и ценам из окружения, задержка минуты; AWS Budgets отстаёт на часы и остаётся страховкой на аккаунт) и `Successes` (ответ дошёл до `done`; штатная метрика Lambda не годится — `error` в SSE для неё успешный вызов). Алармы: расход за сутки > $40; ноль успехов за 3 часа при `Invocations ≥ min_invocations_for_alarm` (без условия по трафику это датчик ночи); прочие по вкусу.

### Конфигурация Lambda

128 МБ, `arm64`, `provided.al2023`, таймаут **50 с**, вне VPC. Таймаут чтения origin на CloudFront — **60 с**, потолок без запроса квоты; функция обязана отваливаться первой, иначе на длинном ответе CloudFront рвёт соединение и пользователь видит обрыв вместо почти готового текста. Вызов модели ограничен дедлайном вызова минус 2 с — запас, чтобы успеть отправить `error`. Клиентский таймаут 60 с держится выше серверного.

### Тесты и запуск

`go test ./...`: конвейер отклоняет до вызова чего-либо, разбор запроса и нормализация языка, длина в code points, кадры SSE однострочны и ошибка под HTTP 200, промпт описывает каждый тон и называет сентинель, удержание начала потока. Bedrock и DynamoDB моками не покрыты — проверяются на стенде: `scripts/smoke-test.sh body.json` вызывает функцию напрямую (буферизованный поток; доставку по частям проверяет только браузер).

## Языки

| Что | Чем определяется |
|---|---|
| Язык интерфейса Chrome (имя, тайтл) | `chrome.i18n`, 30 локалей `_locales` |
| Язык панели | английский, всегда |
| Язык вывода | параметр `lang`; по умолчанию язык браузера, перебивается выбором пользователя, запоминается |

57 языков вывода, список одинаков на клиенте (`code + label`) и сервере (`LANGUAGES` + таблица имён). Варианты не разделяются: `pt-BR`/`pt-PT` → `pt`, `zh-*` → `zh` (в промпте — Chinese (Simplified)), региональные субтеги отбрасываются. Алиасы `no`→`nb`, `iw`→`he`, `fil`→`tl`, `in`→`id`. На клиенте неизвестный язык браузера → `en`; на сервере неизвестный код → `unsupported_language`, подмена запрещена. Клиентский список не может быть шире серверного. Исходный язык текста не определяется и не передаётся — модель читает его сама.

## Приватность

**Сервер не хранит пользовательский текст нигде и никогда.** Обработка stateless, серверный кэш текстов запрещён, в CloudWatch текст не пишется. В DynamoDB — счётчики по `deviceId` и ручные переопределения. **На клиенте текста в хранилище тоже нет:** один результат в памяти панели; передача в окно вывода — через `storage.session` (память). Формулировка в описании и интерфейсе: текст не уходит с устройства никуда, кроме нашего сервера, и не сохраняется ни там, ни здесь.

IP-адреса не собираются: страну определяет CloudFront и передаёт кодом. `X-Device-Id` вырезан из логов WAF через `redacted_fields`.

## Состояния ответа

| Состояние | Условие | Пользователь видит |
|---|---|---|
| Отказ на входе | длина вне `[50, 30 000]` | подсказка под полем, кнопка неактивна; сервер не вызывается |
| Сокращать нечего | модель написала сентинель | сообщение по `nothing_to_shorten`, ввод остаётся |
| Результат | иначе | текст короче, тем же голосом, на выбранном языке |

Проверяется только длина. Эвристик осмысленности нет ни на клиенте, ни на сервере: решает модель. Единственное исключение — `isProbablyReaderable` по DOM перед извлечением страницы: это вопрос «есть ли здесь статья», решается там, где ещё есть разметка.

## Инфраструктура

Один корень `infra/terraform`, модули `api`, `cdn`, `data`, `landing`, `budget`, `artifacts`, `bot`. Состояние — S3 с версионированием и блокировкой, бакет создан отдельно. **Окружение одно — prod;** отладка идёт против него распакованной сборкой с `EXTENSION_KEY` и переопределением лимитов по своему `deviceId`. Именование `mis-<компонент>`, теги `Project = make-it-shorter`, `ManagedBy = terraform`.

- **`api`:** Lambda из S3 (`s3_key = lambda_version`), Function URL `AWS_IAM` + `RESPONSE_STREAM`, вызов разрешён только `cloudfront.amazonaws.com` с условием на ARN дистрибуции. IAM без wildcard: Bedrock по ARN inference profile и каждой региональной модели, куда он маршрутизирует; `GetItem`/`UpdateItem` на одну таблицу; `PutMetricData`; своя log group. `reserved_concurrency` — `null`, пока потолок аккаунта 10 (AWS отклоняет резерв, оставляющий меньше 10).
- **`cdn`:** CloudFront с OAC (`origin_type = lambda`, `signing_behavior = always`), кэш отключён, `origin_read_timeout = 60`, проброс заголовков `X-Device-Id`, `Origin`, `Content-Type`, `x-amz-content-sha256`, `CloudFront-Viewer-Country`. WAF `scope = CLOUDFRONT`: rate-based 60/5 мин на IP; byte-match `Origin STARTS_WITH chrome-extension://`, остальное 403; `AWSManagedRulesCommonRuleSet` (правило `SizeRestrictions_BODY` в `count` — тело запроса регулярно больше 8 КБ). ACM в `us-east-1`, ALIAS `api`.
- **`data`:** DynamoDB `PAY_PER_REQUEST`, hash key `pk`, TTL по `ttl`, **PITR включён** ради ручных переопределений.
- **`landing`:** приватный S3 + CloudFront с OAC, кэш включён (`Managed-CachingOptimized`; HTML 5 мин, хэшированные ассеты год, остальное час; строка запроса не в ключе — `/rate-us?stars=N` одна страница). CloudFront Function на viewer request дописывает `/index.html` к путям без расширения — иначе `/welcome` отдаёт 403. Инвалидация `/*` при выкате.
- **`budget`:** аларм на суточную сумму `EstimatedCostUsd`, аларм «ноль успехов при трафике» через metric math, `aws_budgets_budget` 50/80/100 % как страховка, SNS на email.
- **`artifacts`:** приватный бакет `mis-artifacts` с версионированием: `lambda/<label>.zip`, `bot/<label>.zip`, `extension/<label>.zip`. Архив расширения хранится потому, что магазин не отдаёт обратно загруженное, а при разборе жалобы нужно знать сборку у пользователей.
- **`bot`:** Telegram-вебхук на Lambda Function URL (`authorization_type = NONE` — Telegram не подписывает), тот же бинарник, что CLI `apps/reporter`. Защита: секретный токен в `X-Telegram-Bot-Api-Secret-Token` (сравнение постоянного времени), белый список чатов (пустой — бот отвечает только id чата), окна отчёта ограничены `30m`, `1h`, `12h`, `24h`, `month`. Секрет `mis-bot` в Secrets Manager с `ignore_changes = [secret_string]`, Terraform его содержимого не знает.

### Выкат

**Скрипт собирает и кладёт, Terraform выкатывает.** `scripts/make-release.sh`: `go test` и сборка бэкенда и репортера под `linux/arm64`, сборка расширения через `frontend-build.sh`, загрузка трёх архивов в S3 под одной меткой (тег на HEAD или короткий sha; занятое имя получает `-1`, `-2`), печать метки. Выкат — правка `lambda_version`/`bot_version` в `terraform.tfvars` и `terraform apply`; откат — та же правка на прежнее значение. Скрипт прав на `UpdateFunctionCode` не имеет: два способа менять прод разошли бы state с реальностью. Расширение в магазин загружается вручную.

Не в Terraform: зона Route53 (через `data`), бакет состояния, доступ к моделям Bedrock (включается в консоли), загрузка в магазин. Ручные ресурсы на время разработки допустимы, но до выката обязаны быть описаны в Terraform или удалены; проверка — развернуть с нуля одним `apply`.

## Приоритеты MVP

Скорость выката. При выборе между «правильно» и «быстро» побеждает быстро, кроме двух пунктов, которые дорого чинить задним числом: stateless-сервер без текстов и минимальные разрешения расширения.
