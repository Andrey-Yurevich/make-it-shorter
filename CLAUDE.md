# make it shorter

Расширение Chrome: сжимает выделенный текст или страницу целиком и предлагает уточняющие кнопки, подобранные под конкретный материал.

Этот файл — сквозные требования: решения, затрагивающие больше одного пакета. Всё, что локально для пакета, — в его спеке.

| Спека | Что описывает |
|---|---|
| `specs/extension/SPEC.md` | Расширение Chrome |
| `specs/backend/SPEC.md` | Lambda-обработчик |
| `specs/infra/SPEC.md` | Terraform |

При конфликте этого файла со спекой пакета прав этот файл.

## Состав системы

| Пакет | Что | Стек |
|---|---|---|
| `apps/extension` | Расширение Chrome MV3 | TypeScript |
| `apps/backend` | Lambda-обработчик | Go |
| `infra/terraform` | Инфраструктура | Terraform |
| `catalog.json` | Каталог кнопок — единственное, что нужно обеим сторонам | JSON |

Расширение на TypeScript, бэкенд на Go. Общего кода между ними нет и быть не может — только общие данные, и они сведены к одному файлу.

## Язык

**Спеки на русском. Всё остальное на английском.**

| На русском | На английском |
|---|---|
| `CLAUDE.md`, `specs/**`, рабочие заметки | код, имена, комментарии |
| обсуждение и ревью | сообщения коммитов, описания PR |
| | промпты к модели, `description` и `instruction` в каталоге |
| | строки логов, сообщения об ошибках в коде |

Пользовательские строки — отдельная история: они живут в `_locales` и переводятся на 30 языков, английский там такой же перевод, как остальные.

Правило простое: то, что читает человек про замысел, — по-русски; то, что живёт в репозитории как исполняемый артефакт, — по-английски. Смешение внутри одного файла хуже любого из вариантов.

## Стиль кода

**Код Lambda пишется наивным и читаемым.** Это требование, а не пожелание, и оно сильнее привычек:

- прямолинейный последовательный код вместо слоёв абстракции;
- интерфейс заводится, когда есть вторая реализация, а не в ожидании её;
- повтор лучше преждевременного обобщения;
- стандартная библиотека и AWS SDK; каждая следующая зависимость требует обоснования;
- явное лучше умного: длинное понятное имя, развёрнутое условие, обычный `if` вместо остроумия;
- никаких фреймворков внедрения зависимостей, генерации кода и рефлексии.

Причина конкретная: функция маленькая, живёт долго и правится редко — раз в несколько месяцев, под давлением, когда что-то сломалось. Читать её будет человек, не помнящий контекста. В этих условиях выигрывает скучный код, который понятен сверху вниз за один проход, а не элегантный, требующий держать в голове три файла.

Правило распространяется и на расширение, но там оно мягче: интерфейс есть интерфейс.

## Что меняется без релиза расширения

Расширение проходит ревью в Chrome Web Store, это дни. Поэтому всё, что может понадобиться срезать срочно, живёт на сервере, а не в сборке расширения:

- пороги длины входа;
- дневная квота на устройство;
- потолки ответа модели и максимум кнопок;
- список языков;
- аварийный выключатель сервиса.

Это переменные окружения Lambda, меняются через `terraform apply`. **Отдельного канала доставки конфига на клиент нет.** Значения применяет сервер, а расширение узнаёт о них из кода ошибки в ответе: `too_short`, `too_long`, `unsupported_language`, `rate_limited`, `service_disabled`. Правка доезжает мгновенно, на первом же запросе, по тому же соединению, что и всё остальное.

Эндпоинт, раздающий конфиг клиенту, рассматривался и отклонён: кэш на клиенте отложил бы аварийный выключатель на срок кэша, а сам запрос — второй канал со своим профилем доступа и своим способом молча не сработать. Выключатель, который едет тем же путём, что и полезная нагрузка, отказывает вместе с ней, а не отдельно от неё.

**Клиентская проверка не должна быть строже серверной.** У расширения свои встроенные пороги и свой список языков; они существуют только чтобы не гонять заведомо мусорный запрос. При расхождении худшее, что случится, — лишний запрос, который сервер отклонит. Ложного отказа на клиенте не будет никогда, и совпадение логики до буквы не требуется.

**Единица счёта длины — Unicode code point, на обеих сторонах.** Это не педантизм: `String.prototype.length` в JS считает UTF-16-юниты, а `len()` в Go — байты, и ни то ни другое не совпадает с интуитивным «символом». На эмодзи и суррогатных парах JS насчитает вдвое больше, на кириллице и CJK Go насчитает вдвое-втрое больше байтов. В обе стороны это ломает правило выше: клиент отклонит текст, который сервер бы принял. Считать нужно code points — `[...str].length` в JS, `utf8.RuneCountInString` в Go.

Отсюда асимметрия, которую надо держать в голове при правке серверных значений: **ужесточение работает сразу, ослабление — только до встроенного порога расширения.** Опустив `minInput` на сервере, старого клиента этим не подвинешь: он отсечёт текст сам. Поэтому встроенные значения выбираются с запасом в сторону мягкости.

## Транспорт

**Один регион: `us-east-1`.** Lambda Function URL с `InvokeMode: RESPONSE_STREAM`, перед ней CloudFront.

Регион выбран по доступности моделей Bedrock: там они появляются раньше и шире всего, а выбор модели ограничивает весь продукт — нужны и strict tool use, и дешёвый быстрый класс.

API Gateway не используется: CloudFront перед функцией нужен в любом случае, шлюз добавил бы звено и стоимость без выигрыша. Стриминг он поддерживает — отказ не по этой причине.

- Перед функцией обязателен CloudFront: Function URL не даёт кастомных доменов.
- Function URL закрыт через OAC — прямые обращения в обход CloudFront отклоняются.
- Function URL не поддерживает стриминг внутри VPC. Функция живёт вне VPC.

### Почему одного региона достаточно

Рукопожатие TLS происходит на ближайшем узле CloudFront, а не в регионе лямбды, и он держит прогретые соединения до origin. Вызов Bedrock идёт внутри региона и от местоположения пользователя не зависит.

Далёкий регион удорожает только **время до первого токена**: запрос и первый токен едут через полмира. Дальше труба уже открыта, и токены идут потоком — каждый следующий не платит round trip заново. Есть постоянное смещение, но частота, с какой текст появляется на экране, не меняется.

Мультирегион купил бы сотни миллисекунд до начала ответа ценой: региональных сертификатов, API Gateway вместо Function URL (иначе нет latency-роутинга), Global Table с неатомарной квотой через границу регионов и агрегации метрик. Для MVP размен не окупается.

## Протокол

SSE. Кодировка UTF-8, `Content-Type: text/event-stream`.

### Формат кадра

```
event: <имя>\ndata: <компактный JSON в одну строку>\n\n
```

Поля `id:` и `retry:` не используются: переподключения с `Last-Event-ID` нет и быть не может — ответ невоспроизводим, повтор означал бы новый запрос к модели и новый счёт.

Многострочный `data:` не встречается никогда: `JSON.stringify` экранирует переводы строк внутри строк сам. Парсер клиента вправе на это опираться.

**Строки-комментарии (`:` в начале) — heartbeat.** Сервер шлёт `: ping` раз в 10 секунд, пока идёт фаза 2. Пауза до 25 секунд между `actions` и первым `answer` штатная, а промежуточные прокси рвут соединения, которые молчат. Клиент комментарии игнорирует по стандарту SSE; неизвестные имена событий — тоже, молча.

| Событие | Payload | Частота |
|---|---|---|
| `delta` | `{text: string}` | много раз, только резюме |
| `actions` | `{ids: string[]}` | ровно один раз |
| `answer` | `{id: string, text: string}` | по одному на каждый ID, целиком |
| `done` | `{tokensIn: number, tokensOut: number}` | один раз, штатное завершение |
| `error` | `{code: ErrorCode, message?: string}` | вместо `done` |

**Порядок жёсткий:** `delta`* → `actions` → `answer`* → `done`. Резюме дописывается только событиями `delta`; тексты уточнений приезжают только событиями `answer` и в `delta` не попадают никогда.

**`actions` и `done` отправляются всегда**, включая случай пустого списка. Без них клиент не отличает «кнопок нет» и «завершено» от оборванного соединения.

`ids` может быть пустым — это валидный результат, а не ошибка. Означает «уточнять тут нечего»: мусорный ввод, слишком короткий текст, отсутствие предмета. Расширение в этом случае показывает резюме без кнопок, не считает это сбоем и ничего не подставляет вместо.

`answer` приходит **целиком**, без стриминга по кускам. Пользователь в этот момент читает резюме, а текста уточнения не видит вообще — стримить то, на что никто не смотрит, значит платить сложностью протокола за невидимое.

**`done` — точка сверки.** ID, приехавший в `actions`, но не получивший своего `answer` к моменту `done`, у клиента отбрасывается: кнопка исчезает. Отдельного кода ошибки на неудавшееся уточнение нет — резюме уже доставлено, и валить весь ответ из-за одного из пяти было бы хуже, чем показать четыре.

`docType` и `srcLang` модель возвращает вместе с кнопками, но клиенту они **не передаются** — расширение с ними ничего не делает. Остаются на сервере, в логах.

### Коды ошибок

`too_short` · `too_long` · `rate_limited` · `unsupported_language` · `upstream_error` · `invalid_request` · `service_disabled`

`service_disabled` — аварийный выключатель. Проверяется первым шагом конвейера, до всего остального. Расширение по нему показывает состояние «сервис временно недоступен» и не отправляет запросов до следующего действия пользователя.

Поле `message` необязательно и приходит только с `service_disabled`: это заданный вручную текст вроде причины и срока, английский, показывается как есть. Его нет — расширение показывает свою локализованную строку. Все остальные коды текста не несут: формулировки для них живут в `_locales`.

## Заголовки запросов

| Заголовок | Обязателен | Назначение |
|---|---|---|
| `X-Device-Id` | да | UUIDv4, генерируется при установке, квоты |
| `X-Catalog-Version` | да | целое, фильтрация ID кнопок под версию клиента |
| `Origin` | да | `chrome-extension://<ID>`, проверяется на WAF |
| `x-amz-content-sha256` | да | SHA-256 тела запроса в hex. Требование OAC: CloudFront не хэширует тело сам, а вписывает в подпись SigV4 значение из этого заголовка; без него Function URL отвечает 403 |

**Все эндпоинты — POST.** GET в API нет, и это не случайность: на POST браузер проставляет `Origin` всегда, а на GET из расширения — не обязательно. Правило WAF «только `chrome-extension://<ID>`» действует на весь API без исключений по путям ровно потому, что исключать нечего.

`Origin` фильтрует WAF на CloudFront, не Lambda: отклонённый запрос не порождает вызова функции. Ответ в этом случае — обычный 403, без SSE. Клиент трактует любой не-200 как транспортную ошибку.

## Кнопки

Три правила, нарушение любого ломает продукт.

1. **Модель никогда не генерирует подписи.** Только идентификаторы из каталога, через strict tool use с enum в схеме.
2. **Отсутствие вызова инструмента — валидный результат.** Означает «уточнять нечего»: мусорный ввод, слишком короткий текст, отсутствие предмета. Подстановка дежурного набора кнопок при пустом результате **запрещена**.
3. **Подписи живут только в расширении.** По сети едут ID. Сервер не знает и не должен знать, как кнопка называется.

### Уточнения генерируются заранее, все сразу

Один запрос клиента даёт и резюме, и готовые ответы на все предложенные кнопки. Нажатие на кнопку **не ходит в сеть** — оно раскрывает уже полученный текст.

Второго запроса за уточнением не существует, и это главное решение в архитектуре ответа. Оно стоит денег: платим за все уточнения всегда, хотя пользователь нажмёт в лучшем случае на одно, а чаще ни на одно. Разменяли осознанно, и вот на что.

**Уточнение пишется, пока исходный текст в руках.** Второй запрос был бы stateless и приносил бы текст заново — от клиента, необязательно тот же самый, уже обрезанный, из истории, где он мог быть урезан при вытеснении. Появлялся целый класс отказов вида «резюме есть, а ответить по нему не из чего»: кнопка обещает уточнение, а материала под ним не осталось. Держать этот класс закрытым конструкцией надёжнее, чем ловить его проверками.

**Исчезает половина протокола и весь второй эндпоинт.** Не нужны: пересылка резюме от клиента и его валидация, правило «шли тот же текст, что в прошлый раз», хранение языка диалога ради связности треда, отдельный лимит на длину присланного резюме, обработка «нажали кнопку у диалога, которого уже нет в истории». Всё это — потенциальные баги, которых теперь нет.

**Мгновенная реакция на нажатие.** Ответ уже на устройстве.

Прямое следствие для денег: **максимум кнопок — это множитель стоимости запроса, а не элемент интерфейса.** Менять его — самый сильный рычаг расхода, сильнее выбора модели.

### Где лежит каталог

`catalog.json` в корне репозитория — единственное место, где список ID определён. Бэкенд собирает из него enum для схемы инструмента. Расширение берёт номер версии для заголовка и на сборке проверяет, что у каждого ID есть подпись во всех локалях.

### Схема

```json
{
  "version": 3,
  "actions": [
    {
      "id": "whats_the_catch",
      "since": 1,
      "description": "когда уместно предложить эту кнопку — критерий выбора для модели",
      "instruction": "что сделать с текстом, когда её нажали — императив для модели",
      "deprecated": false
    }
  ]
}
```

| Поле | Обязательно | Кто читает |
|---|---|---|
| `version` | да | расширение (заголовок), тесты сборки |
| `id` | да | обе стороны, сеть, ключ локалей |
| `since` | да | сервер, фильтрация под версию клиента |
| `description` | да | сервер — в системный промпт рядом с enum |
| `instruction` | да | сервер — в промпт фазы 2, где пишется уточнение |
| `deprecated` | нет, по умолчанию `false` | сервер |

`description` и `instruction` — **на английском и только для модели**. Пользователь их не видит, локализации они не требуют. Это не нарушает правило 3: подписи по-прежнему живут только в расширении, а в каталоге лежит машинный текст, который наружу не показывается никогда.

Без `description` enum бессмыслен: модель видит список идентификаторов и выбирает наугад. Без `instruction` нечего отправить модели в фазе 2 — по одному ID не восстановить, что от неё хотят.

**`id` неизменен навсегда.** Он едет по сети и служит ключом в `_locales/<lang>/buttons.json`. Переименование ломает оба места разом, причём у всех установленных сборок сразу: сервер начнёт присылать ID, к которому у расширения нет подписи. Ошиблись в имени — заводится новый ID, старый помечается `deprecated`.

### Версионирование каталога

`since: number` — версия каталога, в которой ID появился.

Сервер отдаёт только ID с `since <= X-Catalog-Version`. Фильтрация **после** ответа модели, на сервере. Помещать версионный фильтр в JSON-схему инструмента запрещено — это порождает разные схемы и дробит prompt-кэш.

Инвариант: **`version` равна максимальному `since` в файле.** Добавили ID — подняли `version` и поставили новому ID `since` = новой версии. Проверяется тестом сборки на обеих сторонах.

Удаление записи из каталога запрещено — только `deprecated: true`. Помеченная запись исключается из enum и из промпта, но остаётся в файле: подпись к ID обязана находиться, пока его может показать хоть одна установленная сборка. Сам `instruction` при этом остаётся рабочим: помеченный ID больше не предлагается, но если он всё же дошёл до фазы 2, писать уточнение есть по чему.

Правка `description` любой записи меняет статическую часть промпта и обнуляет prompt-кэш целиком. Это допустимо, но не бесплатно: мелкие косметические правки формулировок копятся и вносятся пачкой, а не по одной.

## Языки

Разделяются три независимые сущности:

| Что | Чем определяется | Где живёт |
|---|---|---|
| Язык интерфейса | `chrome.i18n` | расширение |
| Язык подписей кнопок | тот же, что интерфейса | расширение, `_locales` |
| Язык резюме и уточнений | параметр `lang` в запросе | передаётся на сервер |

**Промпт всегда на английском.** Локализация промпта запрещена: дробит prompt-кэш по числу языков, ухудшает следование инструкциям, требует синхронной правки N версий.

**Исходный язык текста не определяется и не передаётся.** Модель читает его сама. Возвращает его в вызове инструмента как `srcLang` — только для логов, клиенту не уходит.

**Язык вывода не определяется по региону или IP.** Источник — `chrome.i18n.getUILanguage()`, перебивается явной настройкой пользователя.

### Нормализация

BCP-47 приводится к белому списку с откатом: `ru-RU` → `ru`, `zh-TW` → `zh-Hant`, неизвестное → `en`.

Разделяются: `pt-BR`/`pt-PT`, `zh-Hans`/`zh-Hant`. Не разделяются: варианты английского, испанского, французского.

Список поддерживаемых кодов задан на обеих сторонах отдельно: на сервере — переменная окружения, в расширении — встроенный список. Нормализация тоже реализуется отдельно; расхождение некритично, пока список расширения не шире серверного. Язык вне серверного списка → `unsupported_language`.

## Приватность

Инвариант: **сервер не хранит пользовательский текст нигде и никогда.**

- Обработка запроса stateless: текст живёт в памяти функции, пока идёт ответ, и исчезает вместе с ним. Серверный кэш текстов запрещён.
- В CloudWatch не пишутся ни исходник, ни резюме, ни тексты уточнений, ни их фрагменты.
- В DynamoDB хранятся счётчик запросов по `deviceId` и, если заведено вручную, переопределения лимитов для конкретного устройства.

**Истории диалогов нет вообще.** Панель держит один диалог — тот, что на экране, — в памяти, и теряет его при закрытии. В `chrome.storage.local` пользовательских текстов не лежит: только `deviceId`, две настройки, версия каталога и флаг оценки. Обещание «текст не сохраняется» относится теперь к обеим сторонам, и формулировка в описании и в интерфейсе должна говорить именно так: текст не уходит с устройства никуда, кроме нашего сервера, и не сохраняется ни там, ни здесь.

Расширение запрашивает доступ ко всем сайтам: иконка на выделении должна работать везде, а заранее знать где — нельзя. При установке Chrome показывает по этому поводу самое пугающее из своих предупреждений, и **описание в магазине обязано объяснять его первым экраном**, а не оставлять пользователя с ним наедине: страница читается только по действию пользователя, фонового чтения нет. Подробности — в спеке расширения.

**IP-адреса не собираются.** Для географических тиров нужна страна, и её определяет CloudFront, передавая функции двухбуквенный код в заголовке. Адрес до кода не доходит.

Поле `email` в переопределениях — персональные данные. Пока оно пустое, обязательств не возникает; как только начнёт заполняться, нужны политика приватности, декларация в Chrome Web Store и способ удалить запись по запросу.

Разрешено логировать: длину входа, `docType`, `srcLang`, выбранные ID, латентность, токены, код ошибки, флаг пустого результата.

## Три состояния ответа

| Состояние | Условие | Что видит пользователь |
|---|---|---|
| Отказ на входе | длина вне `[minInput, maxInput]` | сообщение, обращения к модели нет |
| Резюме без кнопок | модель не вызвала инструмент | только текст |
| Резюме с кнопками | инструмент вызван | текст + 3–5 кнопок с готовыми ответами внутри |

Проверяется только длина — на клиенте и повторно на сервере. Эвристик «осмысленный ли текст» нет: решать это — работа модели, она же не вызывает инструмент, когда уточнять нечего.

Четвёртого состояния «кнопка нажата, ждём ответа» не существует: к моменту, когда кнопка стала активной, её текст уже на устройстве.

## Лимиты

| Параметр | Значение |
|---|---|
| Минимум входа | 50 символов после нормализации |
| Максимум входа | 30 000 символов |
| Единица счёта длины | Unicode code point |
| Максимум кнопок | 5 |
| Квота | 50 запросов в сутки на устройство |
| Потолок резюме | 400 токенов |
| Потолок одного уточнения | 250 токенов |
| Порог алярма по расходу | $40 в сутки |

Потолков теперь два, и второй умножается на число кнопок. Худший случай одного запроса — 400 + 5 × 250 = **1650 выходных токенов** против прежних 400. Порог алярма поднят соответственно; прежние $20 срабатывали бы на обычном трафике.

Модель, квота и оба потолка разрешаются на каждый запрос по цепочке: **переопределение для устройства → набор для географического тира.** Оба уровня меняются без релиза расширения.

Набор тира задан в окружении целиком, и это общее правило: **всякий дефолт выписан в переменных окружения лямбды явно.** Пустое значение не означает «возьми откуда-нибудь ещё» — за действующим числом не надо идти в код. Глобальный дефолт от этого не пропал, но стал уровнем Terraform, а не рантайма: `default_*` — база, на которую накладываются оба набора при сборке окружения, и функция её не видит. Единственное исключение — `MAX_ACTIONS`: оно уезжает в промпт до первой точки кэширования и обязано быть одним для всех.

Значения в таблице — стартовые. Действующие живут в переменных окружения Lambda и меняются без релиза расширения, см. одноимённый раздел. Расширение о правке не узнаёт и продолжает работать по своей встроенной копии — на результат это не влияет, потому что решает сервер.

Квота и потолок токенов расширению не сообщаются вовсе: остаток запросов пользователю не показывается — на старте это лишний элемент интерфейса. При исчерпании приходит `rate_limited`, расширение показывает сообщение.

## Приоритеты MVP

Скорость выката. При выборе между «правильно» и «быстро» побеждает быстро — **кроме** трёх пунктов, которые дорого чинить задним числом:

1. Версия каталога в протоколе.
2. Проверка ID на сервере.
3. Stateless-сервер.
