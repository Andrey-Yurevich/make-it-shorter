# Картинки в результате: план внедрения

Временный рабочий документ на русском. Не коммитить: после реализации решения переезжают в CLAUDE.md, файл удаляется.

Дата: 2026-09-20. Статус: план согласован, к реализации.

## Цель

Картинки исходной статьи или выделения появляются в сокращённом тексте на тех же местах. Текст по-прежнему сокращает модель. URL картинок не покидают устройство.

## Ключевое решение: маркеры вместо URL

Обходчик `content/structure.ts` заменяет каждую пригодную картинку маркером `{{img:N}}` (N с единицы, в порядке документа) и собирает таблицу `{id, src, alt}` рядом с текстом. Модель видит только маркеры и обязана сохранять их на месте. Панель при рендере подменяет маркер на `<img>` по номеру из своей таблицы.

Почему так:

- URL картинок не покидают устройство. Сервер получает только текст, формулировка приватности держится дословно.
- Маркер стоит около пяти токенов и не искажается. Длинный URL модель портит, и он ест лимит длины на входе и токены на выходе.
- Сервер о картинках не знает. Единственная правка там один абзац промпта и тест.

Маркер начинается с `{{`, а не с `[[`, чтобы не пересекаться с удержанием сентинеля `[[NOTHING_TO_SHORTEN]]` на сервере. Для remark это обычный текст.

Форма маркера это общие данные обеих сторон, как коды ошибок. Каждая сторона держит свою копию. Контракт проверяется тестами: на клиенте регулярка распознаёт `{{img:1}}`, на сервере промпт содержит `{{img:`.

## Что где меняется

### 1. Извлечение: `apps/extension/src/content/structure.ts`

- `img` и `picture` уходят из `SKIPPED_TAGS`. `picture` рендерит только свой `<img>`, `<source>` игнорируется.
- Кандидаты URL по порядку: `src`, если не пустой и не `data:`; затем `data-src`, `data-lazy-src`, первый кандидат `srcset`, первый кандидат `data-srcset`. На пути страницы Readability уже сделал `_fixLazyImages` и `_fixRelativeUris`. На пути выделения это делает обходчик.
- Относительные URL. Свойство `img.src` на клоне разрешается относительно живого документа, потому что клон остаётся в `ownerDocument`. Атрибуты `data-*` разрешаются через `new URL(value, document.baseURI)`.
- Принимается только `https:`. `http:` поднимается до `https:`, иначе панель заблокирует его как mixed content. `data:`, `blob:`, `file:`, `chrome:` отбрасываются без маркера: `data:` слишком большой, `blob:` привязан к origin страницы и из расширения не грузится.
- Атрибут `width` или `height` меньше порога: пропуск. Так уходят пиксели-трекеры и иконки. Без атрибутов картинка остаётся: на отсоединённом документе размеров нет.
- Лимит на число картинок за одно извлечение. Дальше картинки выбрасываются молча, без маркера.
- Литеральное `{{img:` в текстовых узлах экранируется в `{ {img:`, чтобы текст страницы не подменял маркер.
- Размещение. `<img>` как блок даёт `\n\n{{img:N}}\n\n`. Внутри `<li>` и ячейки таблицы маркер стоит инлайн в строке. `figcaption` уже блок, поэтому подпись идёт абзацем после маркера, и модель может её сократить или выбросить.
- Сигнатуры. `textWithStructure(root)` и `selectionWithStructure(selection)` возвращают `{text, images}`. Нумерация сквозная по всем диапазонам выделения.
- Откаты `body.innerText` и `selection.toString()` остаются без картинок.
- Обрезка до максимума входа. Маркер, разрезанный обрезкой, безвреден. Записи таблицы, на которые текст не ссылается, просто не рендерятся.
- Минимум длины на клиенте считается вместе с маркерами, как и на сервере. Клиентская проверка не становится строже серверной.

Тесты: `img` в абзаце; lazy-load через `data-src` и `srcset`; `data:` без запасного URL; `http:` в `https:`; пиксель 1×1; `picture`; `figure` с подписью; лимит; экранирование; картинка в `li` и в `td`; относительный URL; выделение, начинающееся внутри `figure`.

### 2. Границы процессов: `apps/extension/src/shared/messaging.ts`

- Тип `ExtractedImage = { id: number; src: string; alt: string }`.
- `ExtractResult` при `ok: true`, `SelectionChangedMessage`, `PanelJob` видов `text` и `fill` получают `images: ExtractedImage[]`.
- Читатели `readExtractResult`, `readSelectionChanged`, `readPanelMessage` сужают `unknown`. Элемент без целого `id`, без `src` строкой с префиксом `https://` или без `alt` строкой выбрасывается. Отсутствие поля даёт пустой массив. Читатели никогда не бросают.
- Service worker в `background/index.ts` пробрасывает поле как есть.
- Тесты в `messaging.test.ts` на каждый читатель.

### 3. Состояние панели: `apps/extension/src/sidepanel/state.ts`

- `images: ExtractedImage[]`: таблица к тексту в поле. Ставится джобом `text` или `fill`. При `edit` сохраняется: правка слова не должна терять картинки. При `unreadable` не трогается.
- `resultImages: ExtractedImage[]`: снимок `images` на `start`. Результат рендерится только по снимку. Иначе новое извлечение после `done` заменило бы таблицу, а старый результат на экране указывал бы на чужие картинки.
- Тесты: снимок на `start`; джоб после `done` не меняет `resultImages`; `edit` сохраняет `images`.

### 4. Рендер: `apps/extension/src/components/MarkdownView.tsx`

- Пропсы: `images?: ExtractedImage[]`, `streaming?: boolean`. Компонент общий для панели и окна вывода.
- Пре-обработка `hydrate(markdown, images, streaming)`:
  - терпимая регулярка `/\{\{?\s*img\s*:\s*(\d+)\s*\}\}?/gi`, чтобы пережить пробелы, регистр и потерянную скобку;
  - известный id, первое вхождение: заменяется на `![](N)`; повтор и неизвестный id удаляются;
  - при `streaming` незакрытый хвост у конца текста, который ещё может стать маркером, скрывается.
- Компонент `img`. `src` из markdown это id; по нему берётся запись таблицы. Нет записи: `null`. URL, написанный моделью в `![...](https://...)`, не загружается никогда.
- Атрибуты: `loading="lazy"`, `decoding="async"`, `referrerPolicy="no-referrer"`, `alt` из таблицы. Классы: `block max-w-full max-h-64 object-contain rounded my-2`.
- `referrerPolicy="no-referrer"` решает две задачи: хост картинки не узнаёт id расширения, а hotlink-защиты обычно пропускают запрос с пустым Referer.
- `onError`: id попадает в состояние `failed`, компонент рендерит `null`. Иконки битого изображения нет. Картинки за логином, с истёкшей подписью и с hotlink-защитой просто исчезают.
- react-markdown v10: `defaultUrlTransform` пропускает относительный `N` без протокола. Закрепить тестом, что `img` получает `src="3"`.
- CSP менять не нужно: у манифеста нет `content_security_policy`, дефолт MV3 не ограничивает `img-src`.

Тесты в новом `hydrate.test.ts`: замена, дубликат, неизвестный id, хвост при стриминге, регистр и пробелы.

### 5. Плейн-текст и Copy: `apps/extension/src/shared/markdown.ts`, `components/CopyButton.tsx`

- `markdownToPlainText` работает по гидрированному markdown. Узел `image` даёт пустую строку вместо alt. Счётчик вывода и половина `text/plain` в Copy картинок не содержат.
- Половина `text/html` берётся из `innerHTML` и получает `<img src="https://…">` сама. Картинки, скрытые по ошибке загрузки, в DOM отсутствуют и в HTML не попадают.

### 6. Окно вывода: `apps/extension/src/shared/storage.ts`, `output/App.tsx`

- `OutputWindowContent` получает `images`. `takeOutputWindowContent` валидирует элементы так же, как читатели messaging.
- `storage.session` это память, правило «текст не на диске» держится.
- `output/App.tsx` передаёт `images` в `MarkdownView`.

### 7. Бэкенд: `apps/backend/prompt.go`, `prompt_test.go`

Абзац в SHAPE после пункта Mixed. Черновик на английском, как весь промпт:

> Image markers. The extension writes `{{img:1}}`, `{{img:2}}`, … where the page had a picture. A marker is not text: it carries no claim and is never counted as one. Keep every marker exactly as written, in its place, when the block around it survives; drop it when that block goes. Never write a marker the source does not contain, never renumber, merge or repeat one. A source that is markers and a few words has no text to shorten.

Оговорка в MARKUP. К списку запретов добавляется `Markdown images`, и следом: `The extension's {{img:N}} markers are the one exception: copy them as they stand.`

Оговорка в WHEN THERE IS NO TEXT: маркеры не считаются текстом.

Тест `TestPromptTellsTheModelTheImageMarker`: промпт содержит `{{img:1}}` и слово `marker`. Константа `imageMarkerExample` рядом с сентинелем.

Серверный переключатель не нужен. Без абзаца маркер для сервера инертный текст, откат промпта это правка `lambda_version` в `terraform.tfvars`.

### 8. Ручная проверка

| Страница | Что смотреть |
|---|---|
| Статья Википедии с инфобоксом и thumbnails | картинки на месте, подписи сокращены, hotlink проходит |
| Новостной сайт с lazy-load через `data-src` и `srcset` | реальные URL, не заглушки |
| Medium или Substack | `figure` с `figcaption` |
| Выделение, начинающееся внутри `figure` | маркер без родителя рендерится |
| Сайт с hotlink-защитой | картинка скрыта, без битой иконки |
| Картинки за логином, Confluence или Notion | скрыты |
| Страница из одних картинок, галерея | `nothing_to_shorten` |
| Тёмная тема | прозрачный PNG виден или принято как есть |
| Copy в Google Docs и в plain-редактор | HTML с картинками, plain без |
| Open in window | картинки на месте |

Прод сейчас на Haiku 4.5. Соблюдение маркеров проверять на ней, а не только на Sonnet 5: это единственный риск плана, который снимается только прогоном.

### 9. CLAUDE.md

Разделы к правке:

- «Форма текста снимается с DOM»: медиа больше не выбрасываются, маркер, фильтры, лимит.
- «Панель»: рендер `img`, `no-referrer`, скрытие при ошибке, плейн-текст без картинок.
- «Хранилище»: `storage.session` несёт таблицу картинок.
- «Границы процессов»: новое поле в сообщениях.
- «Bedrock и промпт»: пункт про маркеры.
- «Приватность»: URL картинок не уходят на сервер; рендер запрашивает картинки у хостов страницы напрямую, с пустым Referer.

## Значения по умолчанию

| Параметр | Значение |
|---|---|
| Форма маркера | `{{img:N}}`, N с единицы |
| Максимум картинок на извлечение | 20 |
| Минимальная сторона по атрибуту | 40 px |
| Рендер | во время стриминга, по мере закрытия маркера |
| Не загрузилась | скрыта целиком |
| Плейн-текст и счётчик | без картинок |
| Переключатель «с картинками» в панели | нет, всегда включено |
| Новые разрешения, CSP, инфраструктура | нет |

## Вне плана

- Подбор кандидата `srcset` под ширину панели. Берётся первый.
- Подложка под прозрачные картинки в тёмной теме.
- `width` и `height` для резервирования места до загрузки.
- Картинки CSS-фоном, inline `<svg>`, постеры видео.

## Порядок выката

1. Бэкенд: промпт и тест, `make-release.sh`, правка `lambda_version`, `terraform apply`. Старые клиенты маркеров не шлют, абзац для них безвреден.
2. Расширение: релиз в магазин. Если ревью магазина обогнало выкат промпта, новые клиенты тоже работают: маркер инертный текст, панель гидрирует то, что модель сохранила.

## Исполнение

| Параметр | Рекомендация |
|---|---|
| Модель | Claude Opus 5 |
| Уровень усилий | high; xhigh, если бюджет не важен |
| Контекстное окно | 1M, дефолт моделей Claude 5, отдельный флаг не нужен |
| Режим | одна сессия, шаги 1–9 по порядку, `npm run build` и `go test ./...` после каждого |

Почему Opus 5, а не Sonnet 5. План точный, но каждый шаг упирается в инварианты CLAUDE.md: границы через `unknown`, ни байта текста в хранилище, code points вместо `length`, наивный стиль, комментарии в голосе проекта. Плюс DOM-эвристики в шаге 1 и два текста, которые должны попасть в голос существующих: абзац промпта и правки CLAUDE.md. Здесь качество суждения экономит раунды ревью. Sonnet 5 годится для шагов 2, 3, 5 и 6 как субагент: это механическая обвязка с тестами.

Почему не Fable 5.1. Вдвое дороже Opus 5, а выигрыш проявляется на длинных задачах с неясной постановкой. Эта задача уже разложена по файлам.

Почему high. Уровень усилий на моделях Claude 5 влияет сильнее, чем раньше, и `high` даёт баланс качества и расхода. `xhigh` это дефолт Claude Code и тоже подходит. `medium` и ниже рискуют пропустить инвариант из CLAUDE.md, `max` не окупится.

Про контекст. CLAUDE.md, затронутые файлы, вывод тестов и сборок за сессию укладываются в несколько сотен тысяч токенов. Окно 1M вмещает сессию без сжатия. Окно 200K тоже сработало бы с одним-двумя сжатиями контекста. Haiku 4.5 с окном 200K не подходит по качеству суждения, не по окну.
