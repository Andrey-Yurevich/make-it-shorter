# Полное описание листинга

Источник: Batch 23, групповая встреча #2, 08.06.26; урок 2.1 «Создаем полное описание».

## Для кого

- Описание пишется для поисковика и модерации, не для пользователей: его почти не читают. Грамматические ошибки некритичны, модерация на них не смотрит.
- Для модерации — прямо писать, что расширение делает, включая ограничения бесплатной версии.
- Полное описание — весь текст листинга после краткого. В отдельные теги не попадает, но это самый большой текст на странице, на который можно влиять.
- Начинают с английского.

## Объём

- 4500 символов с пробелами, допуск ±100–200. Лимит стора в 16 000 — не ориентир. Меньше 3000 — оптимизированное описание не получится.
- Почему не больше: ~30 ключей подобраны под 4500. Поисковик считает частоту ключей пропорционально длине, модерация — в абсолютных числах. На длинном тексте нужная поисковику пропорция даёт число вхождений, которое не проходит модерацию.
- 10–16 абзацев, не меньше 10. «Вода» допустима в меру.
- Ключей не хватает — описание не сокращать; пустые ячейки таблицы ключей заполнить названием.

## Ключи

Две таблицы из Semrush, в каждой от 15 ключей (по чек-листу урока 15–20 строк), всего ~30 на описание. В описании должны быть высоко-, средне- и низкочастотные ключи.

- **Main Keywords:** Keyword Magic Tool → Broad Match по ключу из названия, верх списка по volume. Все ключи содержат название; минимум половина (7–8) — точным вхождением, в остальных название может разрываться другими словами или переставляться (`incognito mode google`).
- **Extra Keywords:** вкладка Related, сортировка по volume вместо похожести. Ключи про тот же продукт, но без всех слов названия (`anonymous browsing`, `private browser`, `incognito tab`).
- Только по теме продукта. Не брать ключи с названием, но про другое: другая платформа (iPhone, Safari), удаление (`uninstall …`), словарные (`what is …`).
- How-to ключи можно, если продукт отвечает на этот вопрос; в Main — 2–4 максимум.
- Ключи с опечатками можно, если есть volume.
- Для ключей описания не проверяют занятость оптимизированными конкурентами и «софтовость»; KD не критичен.
- В одной таблице не хватило — добрать в другую на недостающее число. Не хватило в обеих — дублировать название.
- Составной ключ, внутри которого другой ключ (`temp number app` ⊃ `temp number`), — два ключа без роста переспама. Использовать чаще.

## Вхождения

- Main Keywords: 15–20 вхождений. Половина (7–10) — ключ из названия как есть, вторая половина — название с хвостом (`ai email generator tool`, `ai email response generator`).
- Extra Keywords: 15–20 вхождений. Не хватает — добрать ключи тем же способом, каким собирали Main Keywords.
- Колонка Times Used — для себя. Вхождение ключа внутри более длинного ключа тоже считается (`incognito mode` в `chrome incognito mode`).
- Вписывать словосочетаниями, а не отдельными словами: `color code picker`, `hex color wheel`, а не `code`, `wheel`.
- Заглавные буквы в ключах убирать примерно в половине вхождений: название BPM Finder → в тексте `Bpm finder`, `bpm finder`. Все ключи с заглавной — пессимизация.
- `best`, `recommended`, `premium` — нельзя: не пропустит модерация.
- `free` — в полном описании можно аккуратно. Если продукт на старте платный — нельзя.

## Структура

- Чем структурнее и больше «воздуха», тем лучше для SEO. Поисковик измеряет пробелы между абзацами и пунктами.
- Абзацы не длиннее 4–5 строк, между абзацами пустая строка.
- Разметки в CWS нет; структура задаётся эмодзи. Эмодзи — маркер пунктов, не украшение, иначе переспам по эмодзи. Все пункты одного списка помечены одним видом эмодзи. Не больше одного эмодзи на строку.
- Обязательно разные типы списков:
  - нумерованные: 1, 2, 3;
  - эмодзи-цифры: 1️⃣, 2️⃣, 3️⃣;
  - буллеты: -, ➤, ▸, •;
  - эмодзи-маркеры: 💡, 📌, 📍;
  - вопрос-ответ — отдельным блоком.
- Пробел между эмодзи и словом всегда, иначе Google может не распознать список.
- Абзацы и списки чередуются: ни сплошных абзацев подряд, ни одних списков.
- Блоки разной формы: пункты разной длины, списки разной высоты (где 2 пункта, где 3, 6, 7).
- Без кавычек.

## Написание

- Лучше писать самому. Текст от ChatGPT допустим за счёт траста домена стора, но доводится вручную.
- Промпт:

```
Work as a professional SEO specialist. Write description for google chrome extension: about 4500 characters, 10-16 paragraphs. Sometimes use emojis, but not more than one per line. Don't use quotation marks. Use lists at least 5 times, for example: 1, 2, 3 and 1️⃣ , 2️⃣ , 3️⃣ and -, ➤, ▸, •. Separate paragraphs with spaces. Also, use the following keywords exactly as they are written and as often as possible. List of the keywords:
- <keyword>
- <keyword>
- ...
```

- Сгенерировать несколько раз, итог собрать из лучших абзацев и списков.
- ChatGPT теряет ключи, забывает списки, пишет сплошным текстом, ставит эмодзи по два подряд. Нет списков — догенерировать или написать вручную.
- Ручная правка: убрать лишние слова, кавычки, повторные эмодзи; добавить высоко-, средне- и низкочастотные ключи из Semrush (насколько позволяет английский); выправить списки.

## Проверка на переспам: Тургенев

- Сервис «Тургенев» (Ашманов). При регистрации даёт 200 ₽ — около 20 проверок; не хватило — второй аккаунт.
- Название, краткое и полное описание вставить одним текстом. Копировать из Google Doc — разметка не ломается.
- Сайдбар показывает число вхождений каждого слова. Серые (предлоги, союзы, частицы) не учитываются.
- Цифра 1 у слова — переспам; насыщенно-красная 2 — гарантированный переспам, убирать.
- Слова из названия держать на границе: либо ровно 1, либо 0, но ещё одно вхождение даст 1. Единица допустима максимум у одного слова, и только у слова из названия. У остальных слов переспама быть не должно.
- Таблица ключей рассчитана с запасом, переспам после первой версии ожидаем. Вычищать, сохраняя максимум ключей: ключ можно перефразировать вместо удаления, освободившееся место отдать другим ключам.
- Закон Ципфа: слова из названия — в топе частот, выше всех остальных значимых слов. То же во вкладке «Словосочетания»: фраза названия выше остальных двусловий.
- Тургенев ошибается: часть значимых слов считает служебными или пропускает (`temp`, `YouTube`). Такие слова считать вручную.
- Итог: на вкладке «Общий риск» — низкий или незначительный.
- Вкладки «Стилистика», «Запросы», «Водность», «Удобочитаемость» игнорировать: они для сайтов, на продвижение расширения не влияют.
